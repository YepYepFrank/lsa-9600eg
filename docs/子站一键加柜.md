# 子站一条命令加柜（0.17.3 起）

> 给子站部署手册用的一节（子站部署手册「一键加柜」指向这里）。脚本 `/opt/lsa9600sp/join-egs.sh`，由一键安装文件 `--role sp` 装上，和 `upgrade-egs.sh` 放在一起。EG 侧的授权与安全见 EG 部署手册 §4a、§6c；设计见 EG 库 `docs/一键加柜方案.md`。
>
> 做法：EG 上只动一次手（装软件时带一行 join-key，可以在进场前的库房做），其余全在子站完成：建本地实体、打配置、推送生效、设转换程序、撤隧道。老办法（现场笔记本 SSH 进 EG，手工 `--sp-key`、provision、pack、拷文件、`install.sh`）照旧能用。

## 1. 一次性准备（子站主机）

```bash
sudo bash /opt/lsa9600sp/join-egs.sh --keygen
```

- 生成隧道 key `keys/eg-tunnel_ed25519`；升级 key `keys/eg-upgrade_ed25519` 已经有（批量升级生成过）就复用，没有就一起生成。都在 `/opt/lsa9600sp/keys/`（root，600）。
- 子站地址取 `docker/.env` 的 `SP_HOST_IP`；取不到或者不对，用 `--sp-addr <子站站内地址>` 给（记住，以后不用再给）。
- 打印一行 **join-key**：
  ```
  LSAJOIN1 192.168.77.20 ssh-ed25519 AAAA…（隧道） ssh-ed25519 AAAA…（升级） 3f2a9c1e
  ```
  里面**只有公钥**，没有任何私密信息：打印、发微信、贴在工单里都没关系。最后 8 位是校验，抄错、少粘一截时 EG 会直接拒绝。
- 重跑 `--keygen` 不会换 key，打印的还是同一行。

## 2. EG 上（一次，库房或现场）

```bash
sudo bash LSA-9600SP-<版本>.run --role eg --lan1 <摄像机网口> --join-key '<上面那一行>'
```

- 整行要加**单引号**。单网口的 EG 不给 `--lan1`。
- 装完就是「**待接入**」：本地 TB 起着，浏览器开 `http://<EG 的 LAN2 地址>/` 是一张只读的待接入页 —— 授权的子站、本机各网口的 IP / MAC、软件版本、本地 TB 起没起，以及子站上要执行的下一条命令。页面上没有任何密钥，也没有任何操作。
- `sudo bash /opt/lsa-eg/install.sh --status` 也会显示「接入：待接入 —— 已授权子站 192.168.77.20」。
- 已经装好的 EG 也可以只补授权：`sudo bash /opt/lsa-eg/install.sh --join-key '<那一行>'`（等于 `--sp-key` 加 `--upgrade-key`，两把 key 都只认子站地址来的连接）。
- 已接入别的子站的 EG 给了别的子站的 join-key：拒绝，要换子站加 `--force`。

## 3. 子站上接入一台

```bash
# 先看能不能接（只看，不改任何东西）
sudo bash /opt/lsa9600sp/join-egs.sh --cabinet AH05 --eg 192.168.10.25 --plan

# 接入
sudo bash /opt/lsa9600sp/join-egs.sh --cabinet AH05 --eg 192.168.10.25
# 带转换程序（缺省串口 / 传感器）
sudo bash /opt/lsa9600sp/join-egs.sh --cabinet AH05 --eg 192.168.10.25 --conv auto
# 指定串口、传感器、从站地址
sudo bash /opt/lsa9600sp/join-egs.sh --cabinet AH05 --eg 192.168.10.25 --conv-serial /dev/ttyUSB0 --sensors pd,gas,temperature --addr pd=2,gas=3
```

`--eg` 是 EG 的 **LAN2 地址**（子站连得到的那个）。`--cabinet` 要是子站 `model.yaml` 里有的柜：没有就先在 model.yaml 加柜，再跑 `scripts/up.sh --prod`。

**步骤**（每步都记在 `/var/log/lsa9600sp/eg-join/<柜号>-<时间>/run.log`）：

| 步 | 做什么 | 重跑时 |
|---|---|---|
| 预检 | 柜号在 model.yaml 里；这个柜没有别的 EG 在线（有就要 `--force`）；EG 的升级入口认得上、版本够（0.17.3 起）、是待接入或者就是这个柜、授权的子站就是本机；隧道账号认得上 | — |
| 1 建实体 | `provision-eg.sh --ssh lsa-sp@<EG> --ssh-key keys/eg-tunnel_ed25519 --eg-url http://<EG>` | 幂等；隧道已撤（已接入本柜）就跳过 |
| 2 打配置包 | `pack-eg.sh --sp <子站> --only <柜号>`，eg.yaml + sp-ca.pem 打成 tar.gz | 照做（几秒） |
| 3 推送并生效 | 经升级入口 `put-config`、`apply-config`；EG 在后台换上配置、起全部服务、自查（7 个容器、agent 连上子站），**失败自己换回**（原来待接入的回到待接入）；子站每 10 s 查一次 | 配置和 EG 上的一模一样就跳过，不重启 |
| 4 等在线 | 子站 eg-list 看到这台上送正常、配置已生效（最多 3 分钟） | 照做 |
| 5 转换程序 | 给了 `--conv` 等参数才做，经入口的 `conv`（参数白名单，见 EG 部署手册 §4a） | 照做（install-conv.sh 只改给了的项） |
| 6 撤隧道 | `drop-tunnel`：删掉 EG 上的隧道账号 lsa-sp；**升级授权留着**（以后批量升级用） | 照做 |

**结果**：最后一张汇总表，每步「完成 / 跳过 / 失败 / 没做」。失败就停在那一步，打印原因和「修好后原样重跑这条命令」—— 前面已做完的会跳过。

常见的失败：

| 提示 | 原因 / 怎么办 |
|---|---|
| 柜号 AH05 不在子站的 model.yaml 里 | 先在 model.yaml 加柜，再跑 up.sh |
| 柜 AH05 已经有别的 EG（…）在线 | 确认是换 EG，加 `--force` |
| 升级入口没授权 | EG 装的时候没带 `--join-key`，或者带的是别的子站的：EG 上重跑 `install.sh --join-key '<本子站那一行>'` |
| EG 版本太老 | EG 先升到 0.17.3（批量升级或手工） |
| 这台 EG 已接入柜 AH03 | 一台 EG 只接一个柜；要改柜先在 EG 上撤（删掉 config/eg.yaml 后重跑 install.sh）再接 |
| 隧道账号认不上 | 隧道已撤（接入过）或 join-key 是别的子站的：EG 上重跑 `install.sh --join-key` |
| 推送并生效失败、已自动换回 | 看汇总里的原因和 EG 上的任务日志（汇总前打印最后 30 行） |

## 4. 一次预检一批

```bash
sudo bash /opt/lsa9600sp/join-egs.sh --from-file 柜号清单.txt --plan
```

清单每行「柜号 EG地址」，`#` 开头是注释：

```
# 3 号站一期
AH05 192.168.10.25
AH06 192.168.10.26
```

逐台给出「能 / 否」和结论，只做预检，不改任何东西；全都能接时退出码 0。**真接入仍然一台一台做**（每台一条 `--cabinet … --eg …`）。

## 5. 接入以后

- 网关页上这台在线、配置已生效；EG 本地页变成正常的管理页。
- 批量升级照常：`sudo bash /opt/lsa9600sp/upgrade-egs.sh --run <新 .run> --only AH05`（升级 key 就是 join-key 里那一把）。
- 以后要再建实体（改设备清单等）：EG 上重跑 `install.sh --join-key '<那一行>'` 补回隧道授权，再在子站重跑 join-egs.sh（配置没变的步骤会跳过）。
