# 气体传感器预热方案（草案 v2，2026-10-11）

> 只是方案，没写代码。气体变送器型号还没定（后端 pending `smokePpm`，T08：「实物型号（MQ-2 烟雾款？）、启动模式与预热」），这里按「通电后 2–3 分钟读数不可信、不管现场设立即启动还是延时启动都一样」设计。型号确定后按 §6 调参数。

## 2. 怎么判断「刚通电」

由 **eg-agent 统一判断**，不靠转换程序，按设备算。下面任意一条成立就进入预热；如果已经在预热中，从这一刻重新计时。型号有 T1 时以 T1 为主，T2 只作兜底：

| # | 触发条件 | 能抓到的情况 | 抓不到的情况 |
|---|---|---|---|
| T1 | **传感器自己报**：型号有预热状态位、上电计数或运行时间寄存器时，转换程序读出来并发 `q:"warmup"`；上电计数变了或运行时间回退也算 | 最准，包括很短的断电 | 要看型号有没有这些寄存器（§6） |
| T2 | **读数长时间中断后恢复**：连续读不到 ≥ `gasGapS`（缺省 **60 s**，可配），之后第一次读到。RS485 偶发读不到十几秒不等于传感器断过电，门限不能按轮询周期算，否则总线一抖就进 3 分钟预热 | 传感器单独掉电较久、485 长时间断线 | 不到 60 s 的掉电（靠 T1 补；没有 T1 的型号接受这个盲区） |
| T3 | **EG 主机刚开机**：`eg.uptime_s` < 预热时长，或 `hostBootId` 变了。**前提：传感器和 EG 同一路电**，按柜可关（`gasBootWarmupOffCabs`，缺省开），现场调试时核实供电关系 | 整柜停电后来电 | 供电不同路时会误进预热，所以要能按柜关 |

- 只是 agent 重启（`agentBootId` 变、主机没重启）**不算**：传感器没断电，不该进预热。
- 预热从「触发后第一次读到数」开始算 `warmupS` 秒，到点自动结束；中途再触发就重新计时。
- 现场设成「延时启动」时，延时期间读数也当预热处理。延时时长是传感器自己的，EG 不读也不用知道；只要 `warmupS` ≥ 延时 + 稳定时间就行。

## 3. 预热期间的数据怎么标

- **照常上送读数，打质量码**：受影响的量标 `q:{"smoke.ppm":"warmup"}`，这一点契约里已经有。不丢数据：现场调试要看预热曲线；也不会因为没数据被看门狗判成「旧值」或「失效」。
- **新增一个数值量 `dev.warmup_s`**：剩余预热秒数，0 表示就绪。EG 对需要预热的设备每个周期都发，没在预热时发 0。用途有两个：本地规则拿它当条件（§4）；子站拿它画趋势图上的「预热中」底色，数值量比解析 `q` 串好查。
- 转换程序发的 `q:"warmup"`（T1）和 agent 判出来的预热，按现有优先级合并。现有缺口：转换程序发的 `q` 没有过期机制，一直有效到它再发新的为止。agent 会给它加一个新鲜度窗口，和 `dev.*` 一样，免得转换程序挂了以后永远停在「预热」。

## 4. 子站和本地规则怎么处理

| 环节 | 处理 | 谁做 |
|---|---|---|
| EG 本地告警规则（烟雾 / 气体越限） | **同一个越限条件分两支**（见下）；TB 规则本来就支持多条件同时满足 | 后端 `tb-alarms.ts` 生成规则；EG 侧不用改 |
| 子站实时页 | `q = warmup` 显示「预热中」，数值灰显 | 后端已有映射，核对一下 |
| 子站趋势图 | 按 `dev.warmup_s > 0` 的时段画「预热中」底色 | 后端、前端 |
| 健康度 / 评分 | 预热期的分项按 NOT_EVALUATED 处理，不按 0 算 | 后端（已有 warmup → NOT_EVALUATED，核对一下） |
| 北向 | 「预热期越限」不推北向；数据点带「无效 / 预热」质量；转成正式告警后照常推 | 后端 |
| 事件记录 | 每次进入预热记一条 info 事件「传感器预热（原因 T1/T2/T3）」，方便以后查误报 | EG（可选） |

**预热期越限不屏蔽，出降级告警**（用户 2026-10-11 定，属安全取舍）。原因：预热期内真的起火、冒烟，也要让值班员看得到；只是预热期读数不可信，不能直接当正式告警自动处置。

| 分支 | 条件 | 告警 | 处理 |
|---|---|---|---|
| 降级 | 越限 且 `dev.warmup_s > 0` | 「预热期读数越限，待复核」，等级 **WARNING** | 只在子站页面提示值班员复核；**不推北向、不走自动确认**；读数回落或预热结束时清除 |
| 正式 | 越限 且 `dev.warmup_s == 0`（加原有持续时间） | 原有的气体越限告警、原等级 | 照常（北向、确认流程都不变）。预热结束后仍越限的，持续时间从就绪时开始算，到点转成正式告警 |

两支用同一个越限阈值，只差 `dev.warmup_s` 这一个条件。不能只生成正式那一支（只在 `dev.warmup_s == 0` 时才判），否则预热期越限完全看不到。

## 5. 预热时长做成可配

- 参数名 `gasWarmupS`：缺省 180，取值 0–900，0 = 不做预热处理。放在子站下发配置 `PUT /api/config` 的 `extras` 里，和 `pm25Abs` 一样：只在下发了时才计入配置哈希，没下发时用缺省值，在子站「阈值 / 参数」页上改。
- 设备级覆盖（可选）：`eg.yaml` 的 `devices[].attrs.warmupS`。沿用 `camRegionLimit` 的做法，从 attrs 读，不改 eg.yaml 的结构。
- `gasGapS`（§2 T2 的门限）：缺省 60，取值 30–600，同样放在 `extras` 里。
- `gasBootWarmupOffCabs`（§2 T3 按柜关）：柜号数组，缺省空（全开），写法同规则的 `offCabs`。供电不同路的柜填进去。

## 6. 型号确定后要再调的

1. **预热时长**：按说明书改缺省值。注意区分「每次上电的预热」（2–3 min）和「新传感器首次使用的老化期」（有的型号要几十小时）。老化期不能靠 `gasWarmupS` 处理，要写进调试流程。
2. **有没有状态寄存器**（预热标志、上电计数、运行时间、故障码）：有的话优先用 T1，T2 和 T3 降为兜底。
3. **预热期的输出是什么**（输出 0、固定值还是逐渐上升）：决定预热期读数在子站要不要隐藏。
4. **延时启动模式**：延时多长、延时期间输出什么、能不能经 Modbus 读出当前模式（`smoke.mode`）。
5. **轮询周期和总线质量**：核实 `gasGapS` 的 60 s 是否合适；**现场供电关系**：传感器和 EG 不同一路电的柜，填进 `gasBootWarmupOffCabs`。
6. **告警阈值和持续时间**：现在 `pm25Abs` / 60 s 是给 PM6 演示用的，要换成该型号的 ppm 阈值。
7. **有没有校准模式**：有的话校准期间标 `calibrating`，处理方式和预热一样。
