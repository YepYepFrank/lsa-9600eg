# 拍板单：一面柜几台 SAM、传感器分开挂时，「缺量」怎么判（W1）

> 2026-10-20，EG 会话起草，交版本协调问用户。只需要在第 4 节选一个。

## 1. 现象

每台 SAM 是一组传感器的「设备名」（如 `SAM-AH03-A`），同事的转换程序按传感器配置它属于哪个设备名，各发各的。

- **照旧一柜一台 EG 的老柜**（一面柜 2–3 台 SAM）：同事现场的接法是按隔室分开 —— A 只接温湿度，B 接局放、弧光、烟雾。`install-conv.sh` 生成配置时也是这个缺省（温湿度挂第一台 SAM，其余挂第二台）。这样 A 永远收不到局放、弧光，B 永远收不到温湿度。
- **舱室 EG（0.18 起，S19 全部是这种）**：一个舱室一台 EG、一台 SAM，五种传感器全挂在这台 `SAM-<单元号>` 下，**不会分开**。S19 现场按现在的接线**不会出现这个问题**。

所以 W1 只跟「一面柜多台 SAM、又照旧一柜一台 EG」的老站有关（开发样机 AH03 这类）。

## 2. 现在各处报什么

| 地方 | 现在怎么判 | 分挂时报什么 | 是否误报 |
|---|---|---|---|
| EG 质量码、通信状态、到达率（本地页「N 个量异常」、子站「离线 / 成功率」） | **0.6.2 起已改**：每台设备该来哪些量，按本机转换程序配置里挂了哪些传感器来算 | 不报（A 只看温湿度，B 只看局放 / 弧光 / 烟雾） | 不误报 |
| 同上，某台 SAM 在转换程序配置里**一个传感器都没挂** | 退回「按整台 SAM 全部测点」 | 这台显示离线、全部量无效 | 一般不是误报（真的没有任何数据）；只有「这台 SAM 本来就是空的」时才算误报 |
| 子站「能力」实况（标了已确认却没采到数据的提示） | 按整个单元合起来看，任一设备名下收到就算有 | 不报 | 不误报 |
| **转换程序检查工具 `lsa_check.py`**（现场调试、`install-conv.sh --check` 用） | 每台 SAM 都按全部测点期望 | A 报「一直没收到 局放 / 弧光…」，B 报「一直没收到 温湿度」，结论「不通过」 | **误报** —— 现在唯一的误报 |

> 另一件容易混的事（不属于 W1）：0.18.1 起子站「SAM 红外」缺省已确认，新装 EG 的转换程序缺省也开红外。非 S19 的站 SAM 没接红外的，要用 `--sensors` 关掉，否则子站会报红外没数据 —— 这是配置问题，发布说明已写。

## 3. 选项

| | 做法 | 改动量 | 风险 |
|---|---|---|---|
| **①** | 检查工具也按**本机转换程序配置**算每台设备该来哪些量（与 EG 本身同一套口径）；`install-conv.sh --check` 自动把配置目录交给它，单独跑时可以手工指定。没有配置时照旧 | 小：检查工具一处 + `--check` 传参 + 自检，约半天，随下一版 | 低：口径与 EG 已在用的一致。传感器挂错设备名时检查工具照样能看出来（该来的没来） |
| ①′ | 检查工具按**单元合并**判断：某个量只要在本单元任一设备名下收到就算有 | 小，约半天 | 中：老柜按隔室区分的意义没了 —— 温湿度挂错到 B 也不报，隔室温度就张冠李戴 |
| ② | 要求转换程序**全部挂在 `SAM-<单元>` 一个设备名下**发 | 对 S19 不用改（本来就是）；对老柜要改同事程序与接线约定、改子站模型 | 高：老柜一面柜多台 SAM 的隔室信息丢掉，子站柜页的隔室显示、北向槽位都要跟着改；与舱室 EG 方向重复 |
| ③ | 维持现状，只在手册写明「检查工具在分挂时会报缺，以 EG 本地页为准」 | 只改文档 | 低，但现场用检查工具时每次都要人工排除这几条「不通过」，容易漏看真问题 |

## 4. 推荐与拍板

**推荐 ①**：EG 本身早已按转换程序配置判断、不误报，只差检查工具没跟上；改成同一套口径，现场跑检查工具就不再出这几条假「不通过」。S19 不受影响（本来就不分挂）。② 动的是老柜的接线约定，代价大、收益小，不建议。
