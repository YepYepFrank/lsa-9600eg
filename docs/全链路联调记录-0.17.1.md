# 全链路联调记录：子站 0.17.1 + EG 0.6.1 + 转换程序 1.1.1（2026-10-16）

> 传感器（模拟）→ 同事的转换程序 → EG 总线 → eg-agent → EG 本地 TB / 本地管理页 → 上送 → 子站 TB / 子站网关页，整条链路在两台干净的沙箱上一次走通。
> 时间一律北京时间。原始时间线在测试机上，关键行抄在下面。

## 结论

- **链路通**：数据、质量码、通信状态、告警、转换程序保险、断子站补传都按设计工作。10 分钟断子站后补传 823 条，用时 1 s，子站侧没有空洞。uv.pulse 本地与子站条数一致（4 = 4），没有重复，也没有丢。
- **转换程序的服务定义已按同事的实际程序落地**（见下面单列的一节）。镜像就是同事 1.1.1 加我方补丁 0001–0005，离线构建，内存实测 19–23 MiB，上限定 128 MB。
- **发现一个要我方改的问题，影响较大（W1）**：eg-agent 的「缺量」判断默认每台 SAM 都接全了各类传感器。同事的实际接法是按隔室分开接：A 只接温湿度，B 接局放、弧光、烟雾。这样一来，两台 SAM **一直是 DEGRADED，永远到不了 ONLINE**，本地页上一直显示「N 个量异常」。子站上 SAM-A 显示「离线」、24 h 成功率 0 %，网关一直「降级」。要先定预期测点从哪里来，见问题清单。
- 同事那边只剩小事：`serial.port` 的默认值，把补丁合进他的仓库，一条日志级别。

## EG conv 服务定义已按实际程序落地

协调会话 10-15 提的几条都已完成，并在本次联调中实际跑过：

| 要求 | 落地 | 联调里怎么验的 |
|---|---|---|
| 地址与串口由 EG 统一给 | 补丁 **0005-E**：`LSA_MQTT_URL`、`LSA_SERIAL` 覆盖 `gateway.yaml` 里的 mqtt 与 `serial.port` | 配置里写的是 `/dev/ttyS1`，测试用 `LSA_SERIAL=/tmp/ttyV0` 覆盖，程序连的就是 `/tmp/ttyV0` |
| 程序读哪里的配置 | compose：`EDGE_GATEWAY_CONFIG=/config`（本机 `config/conv/`），数据与心跳在 `config/conv-data/`，`eg.yaml` 只读挂进去 | 改 `config/conv/sensors/*.yaml` 后 `docker restart lsa-eg-conv` 生效（场景 1、2 都靠它换温湿度挂的设备） |
| 首次自动生成配置 | `install.sh` 发现 `config/conv/` 是空的，就从镜像里的模板（`/app/config.default`）生成：设备名的柜号换成本柜的，串口写 `/dev/ttyS1`。已经有配置的不覆盖 | 沙箱 EG 上生成的就是 `SAM-AH07-*`、`/dev/ttyS1` |

### 环境与测试本身（不是产品问题）

- 沙箱用的精简 `ubuntu:24.04` 没有 `openssl`、`curl`，子站的 `gen-certs.sh`、`check.sh` 要用到。`it-lib.sh` 在沙箱里补了两个替身，用的是离线包里已有的镜像。真的 Ubuntu Server 自带这两个。
- 子站沙箱没有对时源，所以 EG 显示「还没测成功过对时」。没有摄像机，所以证据裁片段一直失败（eg-video：path not configured），30 s 重试一次。
- 测试脚本第一次停 sim 用的是 `pkill`，conv 镜像（slim）里没有，第 4 段等于没做。后来按 /proc 找进程、走 `sh -c kill` 重做。第 4 段同时拆成 4a（传感器全断）和 4b（转换程序卡死）两段，这样才能把「保险不该重启」和「该重启」都验到。
