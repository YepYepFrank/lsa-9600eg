## 1. 摄像机源（与型号无关）

eg-video 里一个「摄像机驱动」提供五样东西，G4 实现 `sim`（仿真器）一种，真机驱动以后加：

| 能力 | 说明 |
|---|---|
| 流地址 | 四路 RTSP（可见光 / 热像 × 主 / 子）；`local.yaml camera.rtsp.*` 手填的优先 |
| 区域配置 | 各测温区的名称、类型（point / line / region / polygon）、坐标，及坐标所在画面的分辨率 |
| 温度 | 全画面最高 / 最低温与最高点坐标；各区域最高 / 最低温与最高点坐标（point 类型只有一个值） |
| 原生报警 | 摄像机自己的报警状态（原样字符串 / JSON） |
| 抓拍 | 可见光 / 热像各一帧 JPEG（G5 用） |

`local.yaml camera.driver`：`sim`（开发 / 演示）｜`onvif` / `rtsp`（只有视频、不测温）｜`restv1`（真机，EG 0.5 起，`apps/video/src/restv1.ts`；摄像机地址 `camera.restv1`，账号口令 `camera.user` / `camera.password`，本地管理页可改）。摄像机口令只在 EG 本地，不上送、不给浏览器。

真机驱动 `restv1` 与上表五样的对应（V1.8）：

| 能力 | 接口 |
|---|---|
| 登录 | `POST /restv1/token`（用户名、口令各取 32 位小写 MD5）→ `accessToken`、`expireTime`（剩余秒数）；之后每个请求头带 `accessToken` |
| 流地址 | `GET /restv1/channel/rtsp/:id`（通道 0 可见光、1 热像）；`local.yaml camera.rtsp.*` 手填的仍优先 |
| 区域配置 | `GET /restv1/measurement/region`（类型、坐标、是否启用；ID 0–11） |
| 温度 | `GET /restv1/measurement/regionTemp`（各区 max / min 带坐标、avg、center；point 类型 `{value, x, y}`）＋ 全画面测温参数接口 |
| 原生报警 | `GET /restv1/alarm/status`（globTemp、regionTemp[]、diffTemp[]、globTempRise …），每秒轮询 |
| 抓拍 | `GET /restv1/channel/snap/:id` → JSON 里的 base64 JPG |

## 2. 遥测：设备 `CAM-<柜号>`（经本机总线 → 本地 TB → 子站，与传感器同一路）

| key | 周期 | 说明 |
|---|---|---|
| `ir.max` `ir.min` | 2 s | 全画面最高 / 最低温 ℃ |
| `ir.max_x` `ir.max_y` | 2 s | 全画面最高点坐标（§4 的坐标系） |
| `ir.R<n>.max` `ir.R<n>.min` | 2 s | 区域 n（1–3）最高 / 最低温 ℃ |
| `ir.R<n>.max_x` `ir.R<n>.max_y` | 2 s | 区域 n 最高点坐标 |
| `ir.R<n>.pt` | 2 s | point 类型的区域只报这一个（不报 max / min / 坐标） |
| `ir.R<n>.rise` | 随 `ir.R<n>.max` | **温升，EG 边缘算**（§3），只对非 point 区域 |
| `cam.online` `cam.fps` `cam.bitrate` | 60 s | 同 §8.5 |
| `cam.rest` | 变化时 + 60 s | 测温接口：OK / **DEGRADED**（温度正常，但区域配置或报警状态读不到，用上一次的；EG 0.5 起）/ FAIL（连不上、口令不对、令牌失效、测温接口报错）；纯 RTSP 驱动不发 |
| `q` `dev.err` | 出错时马上发、失败期间每 10 s 重发、恢复时发一次 | **eg-video 自己发的来源质量码**（EG 0.5 起，不等 agent 按周期判陈旧）：FAIL 时平时发的温度量与 `cam.alarm` 标 `invalid`，`dev.err` = CONNECT / TIMEOUT / AUTH / TOKEN / API / DATA；只是报警状态读不到时只标 `cam.alarm`、`dev.err` = ALARM；恢复后 `q` = `{}`、`dev.err` = 空。agent 照常与它自己看护的结果合并后再发 |
| `cam.alarm` | 变化时 + 60 s | 摄像机原生报警状态（原样）；**默认不建子站告警、只记录**（免得与本地过温规则重复计），映射留待 T12。真机取自每秒轮询的 `/restv1/alarm/status`（推送不发恢复、不支持 HTTPS，不用；CAM6） |

- ~~不报 avg / center~~（2026-10-10 厂家 CAM2 已澄清：avg = 平均温、center = 中心点温度）。**真机驱动起补报**全画面与各非 point 区域的平均温、中心点温度：`ir.avg` `ir.center`、`ir.R<n>.avg` `ir.R<n>.center`（℃、2 s、cap thermalRegions、optional；只显示，**不进告警、不进北向**；2026-10-10 与后端商定，点目录随 I18 加）。全画面热点与区域最高点仍分字段，不混。
- 区域数：摄像机最多 12 个（接口 ID 0–11 对应 R1–R12，CAM4）。**model.yaml 每柜配了几个 `regions.R<n>` 就是几个（最少 1、最多 12，缺省 3）**，经 eg.yaml 的 CAM 设备属性带到 EG，eg.yaml 不加字段（2026-10-10 与后端商定，EG 0.5 起：eg-video 编号、agent 温升 / 汇总量 / 质量码、本地页都按它；点目录 @lsa/points v1.3）。摄像机上的区域名是 `R1`–`R12` 时按名对应，否则按启用顺序编号。北向（Modbus / 104）的地址块不变：仍只有 R1–R3 的独立点；SAM 块的 `ir.t_max` / `ir.rise` 含义改为「对着这个隔室的全部测温区中取最大」（后端在北向接口说明里写明）。
- 摄像机 1 s 刷新、允许每秒轮询（CAM4）：真机驱动每秒取一次（全画面、各区温度、报警状态各一个请求；区域配置 60 s 重读一次、区域条数变了马上重读），上报仍按 2 s 取最新一次（不改点目录周期）。
- 真机驱动只用一个令牌（摄像机最多 2 个会话，另一个留给现场调试工具）；令牌到期前（剩余 10%，5–60 s）重取，任何接口回 10009 立即重取一次再试。登录回 19999 多半是会话满了（调试工具占着），报 API、页面提示关掉调试工具。
- 取不到的量不发（不发 null、不发 0 冒充）；整台摄像机连不上时各量停发，由 agent 的质量码看护标 `stale` / `invalid`。

## 3. 温升（agent 算，派生量）

`ir.R<n>.rise = ir.R<n>.max − env.t`

- `env.t` 取**本柜柜内空气温度**：`eg.yaml` 里 CAM 设备属性 `regions.R<n>.env` 指定的设备（从子站 model.yaml 来）；没指定时取本柜第一台 SAM。
- 两个输入都有效（质量码不是 stale / invalid）且源时间差 ≤ **容差**才输出；容差默认 = 1.5 × `env.t` 的周期 = **15 s**（env.t 10 s 一个，按 10 s 会因时序抖动频繁不出值），`local.yaml derive.riseToleranceS` 可改。
- 输出的时间戳 = `ir.R<n>.max` 的时间戳。允许负值、不钳 0；不用摄像机参数里的环境温度 / 湿度。
- 不出值时在 `CAM-<柜号>` 的质量码 `q` 里标 `ir.R<n>.rise`：输入 stale / invalid → 跟随输入；时间差超容差 → `stale`。

## 4. 区域元数据：`CAM-<柜号>` 客户端属性

```json
"ir.regions": [ { "id": "R1", "name": "断路器触头", "label": "测温区 R1", "type": "region",
                  "coords": { "x": 40, "y": 60, "width": 120, "height": 80 }, "frame": { "w": 640, "h": 480 } } ],
"ir.regionsVer": "a1b2c3d4"
```

- `coords` 原样照摄像机（point `{x,y}`、line `{startX,startY,endX,endY}`、region `{x,y,width,height}`、polygon `{points:[{x,y}…]}`），`frame` 是坐标所在画面（热像主码流）的分辨率，**640×480**（厂家 CAM5；此前按 640×512 写的仿真器、点目录 `FRAME` 待改）。**坐标系已定（厂家 CAM3，G4-4 关闭）：原点左上角、单位像素、热像主码流画面**；画面翻转 / 镜像后坐标不跟着变 —— 画好区域后不要再翻转画面，翻转了要在摄像机上重画区域（部署手册 §5a）。point 类型的 coords 是 `{x, y}`（摄像机返回 `{value, x, y}`，value 进 `ir.R<n>.pt`）。
- `label`：R1–R3 与部位的对应**只来自配置**（`eg.yaml` CAM 设备属性 `regions.R<n>.label`，由子站 model.yaml 给），缺省「测温区 R1」…；**不自动等同 A / B / C 相**。
- `ir.regionsVer`：区域配置的摘要（变了就变），agent 在变化时与每次连上总线时上报；子站据此刷新画框。

## 5. 本地 TB 告警规则（后端 model.yaml / provision 生成，EG 这边需要的形态）

设备配置 `camera`（CAM-<柜号>），每个区域 n = 1..3 各一组，阈值仍来自阈值表：

| 告警类型 | 条件 | 恢复 |
|---|---|---|
| 过温 | `ir.R<n>.rise` > rise（MAJOR，持续 60 s）/ > rise2（CRITICAL，持续 10 s） | ≤ rise − 3 |
| 绝对超温 | `ir.R<n>.max` > tabs（CRITICAL） | ≤ tabs − 5 |
| 区域温差（原「三相温差」） | 任两区 `ir.R<i>.max − ir.R<j>.max` > 阈值 —— TB 设备配置的条件只能比常量，**由 agent 另算派生量 `ir.dmax`**（各非 point 区域 max 的极差，随温度 2 s）再判 | ≤ 阈值 − 3 |

告警明细沿用 `{rule, key, value, threshold, src, cls}`，`key` 带区域号（如 `ir.R2.rise`），子站按 key 取区域显示。`ir.dmax` 需加进点表目录。

## 5b. 汇总量（2026-09-27 补充，已定）

TB 同一设备同一告警类型只有一条活动告警，「每区域一组同类型规则」会互相清除、2 s 抖一次；改成每区域不同类型又会破坏 7 类告警的约定。所以 agent 再派生三个汇总量（与 `ir.dmax` 同一时间戳），本地规则每类一条按它们判：

| key | 说明 |
|---|---|
| `ir.rise` | 各区域 `ir.R<n>.rise` 的最大值；都算不出时不出值、质量码标 `ir.rise` |
| `ir.rmax` | 各区域最高温的最大值（point 用 `.pt`） |
| `ir.hot` | 温升最高的区域号 1–3（没有温升时取最高温最高的区域） |

规则：过温 `ir.rise` > rise / rise2、绝对超温 `ir.rmax` > tabs、区域温差 `ir.dmax` > dphase；告警明细带 `ir.hot`（条件里加恒真的 `ir.hot ≥ 1` 以便模板引用），子站据此显示是哪个区域。上面 §5 的「每个区域一组」作废。

## 6. 仿真摄像机（EG 仿真器 `packages/emu`，开发与 `g4:verify` 用）

- **视频**：RTSP 测试源（mediamtx + ffmpeg 按需出四路测试画面，热像为伪彩），`camera` 容器，开发端口 127.0.0.1:18555。热像主码流测试画面与区域坐标画面现在还是 640×512，随真机驱动（I18）改成 640×480。
- **测温**：按本柜的仿真计划出 R1–R3 与全画面温度（与子站模拟器同一套发生器，温升随负荷与日波动变化；AH03 保留「6 小时内爬升到越限」的预埋异常）。eg-video 的 `sim` 驱动每 2 s 从仿真器取。
- **控制面**（仿真器 `http://127.0.0.1:3190`）：

| 接口 | 作用 |
|---|---|
| `POST /emu/cam/overtemp?region=R2&max=95&s=120` | 区域 R2 最高温 s 秒内保持 95 ℃（测过温 / 绝对超温 / 区域温差） |
| `POST /emu/cam/stream?ch=visible\|thermal\|all&on=0\|1` | 断 / 恢复视频流（测 cam.online、子站播放失败提示） |
| `POST /emu/cam/dead?on=1\|0` | 整台摄像机失联（测温停、流断） |
| `POST /emu/cam/regions` | 改区域配置（JSON：数量、类型、坐标），测 `ir.regionsVer` 与子站画框刷新 |
