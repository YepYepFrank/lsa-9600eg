# G5 循环录像、证据锁定与上传约定（送协调会话审，定稿后作后端库《EG独立TB调整方案》§8.7）

> 2026-09-27。依据：交接说明 V3.0 §14（双端实况、循环录像与证据管理）、开发计划 v0.4 §6.4、§8.2 告警事件、§8.5 视频、§8.6 摄像机测温。
> 标「待确认」的参数先按括号里的做，都做成 `local.yaml evidence` 段的配置。

## 1. 边缘循环录像：录两路子码流，不停

交接说明 §14.1：录像要覆盖故障**前**，所以**边缘不能「没人看就不拉」**，可停的只是子站观看的那一级。据此修订 §8.5：

| 路 | EG mediamtx | 用途 |
|---|---|---|
| `<柜号>-sub`、`<柜号>-ir-sub`（两路子码流） | **一直拉、一直录**（`sourceOnDemand: false`、`record: yes`） | 循环录像、证据片段 |
| `<柜号>`、`<柜号>-ir`（两路主码流） | 仍按需拉（有人看 / 抓拍时） | 单窗观看、抓拍 |
| 子站 → EG 各路 | 仍按需拉 | 观看 |

- mediamtx 自己录：fMP4、每段 60 s、按 `ringHours` 自动删最旧的段（`recordDeleteAfter`）；片段裁切用 mediamtx 自带的回放服务（`/get?path=&start=&duration=`，只听本机）。
- **为什么只录子码流**（§14.4 的算法：两路码率之和 Mbit/s × 秒 ÷ 8 = MB）：

| 录什么 | 码率假设 | 每柜每天 | 128 GB 盘能录 |
|---|---|---|---|
| 两路子码流（默认） | 0.5 + 0.5 = 1 Mbit/s | **10.8 GB** | 留 24 h 循环 + 证据 ≤ 20 GB，富余 |
| 两路主码流 | 可见光 4 + 热像 2 = 6 Mbit/s | 64.8 GB | 最多约 1 天，且 SSD 每天写 65 GB，工业盘寿命吃紧 |

  码率是假设（厂家文档示例子码流 512 kbps、可见光主码流 8 Mbit/s），实机测了再改。子码流画面（640×360 / 320×256 级）够看清故障前后的变化；要主码流级别的画面时靠告警瞬间的**抓拍**（主码流单帧）。
- 录像健康：eg-video 每分钟看两路是否在录、最新一段是否 < 2 分钟前，报 EG 自身指标 `eg.rec_ok`（bool）；断流期间的缺口记下来（证据的 `missingReason`）。

## 2. 证据的三种

| kind | 来源 | channelId | 窗口（缺省，待确认） |
|---|---|---|---|
| `video` | 循环录像裁一段（fMP4 → MP4） | `visible` / `ir` | 前 30 s、后 60 s（交接说明的示例） |
| `image` | 告警瞬间抓主码流一帧（eg-video 抓帧，G4） | `visible` / `ir` | 触发时刻 |
| `wave`（录波） | agent 从本机总线收的传感器数据环形缓冲 | `data` | 前 10 s、后 20 s（现契约 §4.2） |

- 一次触发出一组：可见光 + 热像各一段视频、各一张图，外加一份录波。**双光不硬同步**：两路各记实际起止，索引里带 `pairOffsetMs`（热像实际起点 − 可见光实际起点）。
- 录波如实记录收到的采样：同事那边 2 s 一个就是 0.5 Hz（要 10 Hz 得同事程序支持，开发计划 §9 仍待答复）。文件格式：`{ trigger, pre, post, rateHz（实测中位数）, series: { "<设备>/<key>": [[ts, v], …] } }`，带时间戳而不假定等间隔。

## 3. 触发与锁定

1. **本地告警**：agent 的告警事件第 1 版（ACTIVE，§8.2）即触发：立刻抓两张图；登记视频与录波，窗口到期（触发 + 后窗 + 5 s）后裁片段、写文件。
2. **子站请求锁定**：`PUT http://<EG>/api/evidence/lock`（服务票据，同 §8.3）

   ```json
   { "requestId": "…", "eventId": "…"|null, "start": 1790280000000, "end": 1790280090000,
     "kinds": ["video", "image", "wave"], "upload": false, "reason": "子站站级告警 / 手动录像" }
   ```
   回执：`{ "requestId", "status": "ACCEPTED" | "EXPIRED" | "PARTIAL", "evidenceIds": [...], "message"? }` —— `start` 早于循环录像最旧的一段为 `EXPIRED`，部分早于为 `PARTIAL`（能锁多少锁多少）；`end` 在将来的，录到 `end` 再裁。`image` 只能对「现在」抓，窗口在过去的请求里略过。
3. 同一时间窗被多个事件锁：片段文件共用一份，每个引用各记一行，**所有引用都到期**才清。

## 4. 证据索引（EG → 子站，与告警事件同一做法）

`POST /ext/eg/<柜号>/evidence`（`X-EG-Token`，每批 ≤ 50 条），体 `{ bootId, batchId, items: [...] }`，回执同 §8.2（`accepted` / `duplicate` / `rejected`，按 `evidenceId` + `revision`）。每条（§14.3 的字段）：

| 字段 | 说明 |
|---|---|
| `evidenceId` | EG 生成、全局唯一：`EV-<柜号>-<yyyyMMddHHmmss>-<kind>-<channel>-<4 位随机>` |
| `revision` | 状态变一次 +1 |
| `eventId` / `requestId` | 本地告警的 eventId（§8.2）/ 子站请求号；可都有 |
| `cabinetId` `gatewayId` `channelId` `kind` | `AH03`、`EG-AH03`、`visible` / `ir` / `data`、`video` / `image` / `wave` |
| `requestedStart` `requestedEnd` `actualStart` `actualEnd` | 毫秒；视频按关键帧裁，实际起止可能外扩 |
| `status` | `RECORDING`（后窗还没到）· `READY`（在 EG 上）· `UPLOADED`（子站已存、已校验）· `EXPIRED`（请求晚于循环覆盖）· `MISSING`（这段没有视频 / 数据）· `DELETED`（按保留期清掉，索引留着） |
| `location` | `edge` / `station` / `both` / `none` |
| `sizeBytes` `codec` `sha256` | 文件大小、`h264` / `jpeg` / `json`、SHA-256 |
| `important` | 是否重要（自动上传，§5） |
| `pairOffsetMs` | 双光实际起点差（仅 video / image） |
| `createdAt` `expiresAt` | 生成时刻；EG 本地副本的清理时刻 |
| `missingReason` | `stream_down`（录像断流）· `gap`（部分缺口，实际起止比请求短）· `no_data`（录波期间没收到数据）· `camera_unreachable` |

- **`UNREACHABLE` 是子站自己的判断**（请求或调取时 EG 不在线），EG 不报；子站已有的归档照样能回放。
- 索引不含摄像机地址、口令。

## 5. 文件：重要的自动上传，其余按需调取

- **重要**（`local.yaml evidence.autoUpload`，待确认；缺省：级别 `CRITICAL`，或类型 `弧光异常` / `过温`）：`READY` 后自动 `PUT /ext/eg/<柜号>/evidence/<evidenceId>/file`（`X-EG-Token`、`Content-Type`、`X-Sha256`，体为文件），子站按 sha256 校验、落盘后回 `{ evidenceId, stored: true, sha256 }` —— EG 收到才把 `status` 改 `UPLOADED`、`location` 改 `both`。同一文件重复上传回同样结果（幂等）。
- **其余**：子站点回放时调 `GET http://<EG>/api/evidence/<evidenceId>/file`（服务票据），EG 流式返回（支持 Range，视频可拖动）；本地已清回 `410` + 索引现状。子站想归档时也可以调 `POST http://<EG>/api/evidence/<evidenceId>/upload` 让 EG 走上传。
- 现有的 `POST /ext/eg/<柜号>/snapshots|recordings`（开发计划 §8 #8，还没实现）由本节取代；子站的 `GET /ext/cabinets/<柜号>/recordings|snapshots` 列表改读证据索引（后端）。

## 6. 保留与容量（`local.yaml evidence`，都待确认）

| 项 | 缺省 | 说明 |
|---|---|---|
| `ringHours` | 24 | 循环录像留多久（mediamtx 按时间删） |
| `preS` / `postS` | 30 / 60 | 视频前后窗 |
| `wavePreS` / `wavePostS` | 10 / 20 | 录波前后窗 |
| `lockedDays` | 30 | 锁定片段在 EG 上留多久（未上传的） |
| `uploadedKeepDays` | 7 | 已上传的 EG 本地副本再留多久 |
| `highWater` / `fullWater` | 85 % / 95 % | 数据盘水位 |

- 清理顺序：① 过了 `ringHours` 的循环段（mediamtx）；② 超 `highWater` 时提前删最旧的循环段；③ 过期的锁定片段（所有引用都到期）；④ 已上传且过了 `uploadedKeepDays` 的本地副本。
- **锁定文件从不无提示覆盖**：只剩锁定文件还超 `fullWater` 时，EG 自身指标 `eg.evid_full = true`、写审计、新的锁定标 `MISSING`（`missingReason: disk_full`），子站据此告警（「证据存储满」，后端定级别）。
- EG 自身指标另加 `eg.evid_pending`（待上传条数）、`eg.rec_ok`（§1）。

## 7. 分工

| 谁 | 做什么 |
|---|---|
| EG 库 | eg-video：子码流常录、mediamtx 回放服务、`/api/video/clip`（裁片段）、录像健康；agent：证据库（SQLite）、录波环形缓冲、告警触发、锁定接口、索引同步与回执、自动上传、文件下载、保留与水位、指标；本地页「证据」；`g5:verify`（仿真告警 / 子站锁定 / 过期 / 断流缺证 / 上传校验 / 水位） |
| 后端库 | `/ext/eg/<柜号>/evidence`（索引、幂等、回执）与 `/evidence/<id>/file`（校验 sha256、落盘）；锁定请求（站级告警时调 EG）；回放时代理 `GET` EG 文件；证据列表 / 完整性；「证据存储满」告警；模拟器按同一协议出证据 |
| 前端库 | 告警详情的证据清单（双光配对、实际起止、缺证原因、位置）、回放 |
