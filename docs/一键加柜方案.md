# 子站一条命令加柜（方案 A）· 方案

> 2026-10-17。目标：EG 上只动一次手（可以在进场前的库房做），其余全在子站完成。放 0.17.3。
> 协调已确认（见 §7 的四条决定），按本方案实现；用法见 `docs/子站一键加柜.md`。
> 在已有的两样东西上扩：provision 隧道（lsa-sp，只能转发到 EG 本机 18080）和批量升级入口（lsa-upg，白名单 + sudoers 只放行一个入口）。不新开账号，不改安全模型。

## 1. EG 上那一条命令

```
sudo bash LSA-9600SP-<版本>.run --role eg --lan1 <网口> --join-key 'LSAJOIN1 192.168.77.20 ssh-ed25519 AAAA…(隧道) ssh-ed25519 AAAA…(升级) 3f2a9c1e'
```

- **join-key**：一行纯文本，子站上 `join-egs.sh --keygen` 打印出来。
  - 格式：`LSAJOIN1 <子站地址> <隧道公钥类型> <隧道公钥> <升级公钥类型> <升级公钥> <校验>`，共 7 段、空格隔开；最后 8 位是前 6 段（单个空格连起来）sha256 的前 8 位。抄错、少粘一截时直接拒绝。
  - 里面**只有公钥**，没有任何私密信息，打印、发微信、贴在工单里都没关系。
- **效果**：等于现在的 `--sp-key` 加 `--upgrade-key`，两把 key 的 `from=` 都锁到子站地址。
  - 隧道账号 lsa-sp 原来没有 `from=`，这里补上。
  - 子站地址另记在 `config/join.json` 里（子站地址、两把 key 的指纹、时间），供待接入页和 `--status` 用。
- **两把 key 分开**：隧道 key 只在接入时用，接入完就撤掉；升级 key 一直保留。子站上分别放在 `/opt/lsa9600sp/keys/eg-tunnel_ed25519` 和 `eg-upgrade_ed25519`（root，600）。
- **「待接入」状态**：有 join.json、还没有 eg.yaml 时就是待接入。现在第一轮装完只起本地 TB，没有本地页，所以新加一个**待接入页**：compose 里的 `pending` 服务（profile `pending`，容器 lsa-eg-pending，同一个应用镜像跑 `node pending.mjs`，只用 Node 自带模块、不加载 eg.yaml、不起 Nest 主程序），和平常一样在 80 口，只读，只认 GET / HEAD，LAN1 照样拒。接入（起全部服务）前先删掉它，回到待接入时再起。页面上显示：
  - 「待接入」；
  - 授权的子站地址；
  - 本机各网口的 IP / MAC、软件版本、本地 TB 状态；
  - 提示「等子站执行 `join-egs.sh --cabinet <柜号> --eg <本机 LAN2 地址>`」。

  页面上没有任何密钥，也没有任何操作。`install.sh --status` 同样显示「接入：待接入 —— 已授权子站 …」；接入以后显示「接入：已接入子站 X（柜号 Y）」。
- **防误接**：
  - 已经接入过（有 eg.yaml）的 EG 又给 `--join-key`，而且子站地址变了：拒绝，要加 `--force` 才换。
  - 子站地址没变：照常更新两把 key（幂等）。

## 2. 升级入口加的动作（ENTRY_VERSION 3，仍是白名单）

| 动作 | 做什么 | 校验 |
|---|---|---|
| `hello` | 多报 `joined=0/1`、柜号、子站地址 | — |
| `put-config <sha256> <字节>` | 从 stdin 收配置包（tar.gz），放 `/var/lib/lsa-upg/config-in/<sha>.tgz`，600 | 不超过 1 MB；核对 sha；tar 里**只许** `eg.yaml`、`sp-ca.pem`、可选的 `conv.args` 三个普通文件（没有目录、链接、`..`），否则删掉并拒绝 |
| `apply-config <sha256>` | 后台任务（和升级任务同一套：`systemd-run` / `setsid`、state（`kind=config`）、日志）：备份现在的 `eg.yaml` / `sp-ca.pem`（没有就记「原来是待接入」）→ 换上新的 → `install.sh` 起全部 → 自查（7 个容器在跑、agent 连上子站，最多 240 s）→ 包里带了 `conv.args` 就设转换程序 → done。和现在的配置一模一样时直接回 `same`，不重启 | 包里 eg.yaml 的子站地址要和 join.json 一致（老办法接入、没有 join.json 的认现在 eg.yaml 里的），不让一个包把 EG 改连到别的子站；已接入的 EG 柜号不能改。**失败就换回旧配置**再跑一次 install.sh：原来待接入的回到待接入，原来已接入的回到旧配置。state 记 rolled-back（换回也失败记 rollback-failed） |
| `conv <选项…>` | 同步调 `install-conv.sh` | 只认这些选项，各自校验：`--serial` 只认 `/dev/ttyS<n>`、`/dev/ttyUSB<n>`、`/dev/ttyACM<n>`、`/dev/serial/by-id/<[A-Za-z0-9._-]+>`；`--sensors` 只认 pd / gas / temperature / arc / infrared；`--addr` 是 `名字=1–247`；`--dev` 是 `名字=设备名`，设备名必须在 eg.yaml 里；`--baud` 只认 1200–115200 里的标准值；另有 `--off`、`--status`。不认的整句拒绝。参数用数组传，不经 shell 拼接 |
| `drop-tunnel` | 同 `install.sh --drop-sp-key` | 只撤 lsa-sp，升级授权留着 |

所有拒绝照旧记 `/var/log/lsa-upg.log`。剩余风险和批量升级相同：持升级 key 等于 root。另外：能推配置的人，也能把 EG 改连到别的子站，所以加了「子站地址要和 join.json 一致、已接入的柜号不能改」这两条。

## 3. 子站侧 `join-egs.sh`（随一键安装包装到 `/opt/lsa9600sp/`，和 upgrade-egs.sh 放在一起）

```
sudo bash join-egs.sh --keygen                                   # 生成隧道 key（升级 key 有就复用），打印 join-key
sudo bash join-egs.sh --cabinet AH05 --eg 192.168.10.25 [--conv auto | --conv-serial … --sensors … --addr … --dev … --baud …] [--plan] [--force]
sudo bash join-egs.sh --from-file 柜号清单.txt --plan            # 一次预检一批（每行「柜号 EG地址」），真接入仍然一台一台做
```

**流程**（每一步都写进 `/var/log/lsa9600sp/eg-join/<柜号>-<时间>/`）：

1. **预检**
   - 柜号要在 model.yaml 里（查 eg-list）。不在就停，提示「先在 model.yaml 加柜，再跑 up.sh」。
   - 这个柜已经有别的 EG 在线时停下，要加 `--force`。
   - 对 EG 跑 `hello`：入口版本要 ≥ 3；状态是待接入，或者就是这个柜（重跑）；子站地址对。
2. **建实体**：`provision-eg.sh --cabinet AH05 --ssh lsa-sp@<EG> --ssh-key keys/eg-tunnel_ed25519 --eg-url http://<EG>`（建实体是幂等的）。
3. **打配置包**：`pack-eg.sh --only AH05` 出 eg.yaml 和 sp-ca.pem，打成 tar.gz。
4. **推送并生效**：`put-config` 再 `apply-config`，每 10 s 查一次 state。EG 上已经是同一份配置（sha 相同）时跳过，重跑不会再重启一遍。
5. **等上线**：用 eg-list 等到这台 uplinkOk、cfgApplied（最多 3 分钟）。
6. **转换程序**：给了 `--conv` 才做，经入口调 `conv`。`auto` 就是 install-conv.sh 的缺省值。
7. **收尾**：`drop-tunnel` 撤掉隧道授权，升级授权保留。

**结果**：一张汇总表，每一步写「完成 / 跳过 / 失败」。失败就停在那一步，并打印「问题、从哪一步重来、命令」。前面各步都是幂等的，修好后原样重跑整条命令即可。`--plan` 只做预检，不改任何东西。

**子站要后端做的**：
- 子站部署手册加「一键加柜」一节；
- 子站 nginx 等不用改：provision-eg 已经支持 `--ssh-key` / `--eg-url`，pack-eg、eg-list 都是现成的。

## 4. 保底

老流程照旧能用：现场笔记本 SSH 进 EG，手工跑 `--sp-key`、provision、pack、拷文件、`install.sh`。两本手册的「一键加柜」一节里，两种做法都写。

## 7. 协调的决定（2026-10-17）

1. join-key 用纯文本一行（带校验位）。
2. 隧道 key 和升级 key 分开：隧道接入完就撤，升级授权保留。
3. 待接入页这一版就做：只读、没有密钥、没有任何操作。
4. 已接入的 EG 换子站必须 `--force`；`--status` 和待接入页都要显示「已接入子站 X」。
5. 另加：`join-egs.sh --plan --from-file <「柜号 EG地址」清单>` 逐台给出预检结论；真接入仍然一台一台做。
6. 方案文档和实现放同一个 PR。

**测出并修掉的问题**：
- **专用账号和本地库容器同 uid（0.17.2 就有）**：新装系统上 `useradd --system` 给 lsa-sp（或 lsa-upg）uid 999，正好是本地库容器 postgres 的 uid。宿主机上看，本地库的进程都成了 lsa-sp 的：`hello` 一直报「lsa-sp 隧道开着」，批量升级永远跳过这台；更糟的是 `--drop-sp-key` / `--drop-upgrade-key` 先 `pkill -u` 账号 —— **会把本地库杀掉**。修：账号 uid 取 900–989 里空着的；`pgrep` / `pkill` 只认这个账号的 sshd 会话（`-f '^sshd'`）；`userdel -f`。iteg 的 lsa-sp 就是 999（修之前建的），撤隧道后本地库照常。
- join-egs.sh `--from-file`：循环里 ssh 吃掉了清单（只预检了第一台）；汇总里中文按字节截成半个字。
- `--join-key` 原来在装完 Docker / 镜像 / .env 之后才核对：挪到最前面。换子站时旧子站的 key 还留在 authorized_keys 里：`--join-key` 改成只留这一个子站。
- 待接入时安装结尾的提示重复了一遍「本地 TB 已起」；`--status` 里换配置任务显示成「apply job … from  to AH07」。
- 换配置的旧配置备份（含令牌）只留最近 3 份。
