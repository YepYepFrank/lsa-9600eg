# 转换程序硬件联调步骤（X26A，EG 0.17.1 / 0.6.1）

> 这个包装在**已经装好 EG**（release-0.17.1 r2）的 X26A 上。启用同事的转换程序，读 485 传感器，数据进 EG。
> 不联网，只用包里的东西。命令都在包目录里跑，要 sudo。

## 包里有什么

| 文件 | 用途 |
|---|---|
| `install-conv.sh` | 一条命令启用、看状态、停用、直接问从站（`--help`） |
| `images-conv.tar.gz`、`CONV_IMAGE.txt` | 转换程序镜像 `lsa-eg-conv:1.1.1-p5`：同事 1.1.1（316e619）+ 我方补丁 A–E，带同事的两个串口诊断脚本 |
| `conv-kit/` | `lsa_check.py`（检查总线上的消息格式，只要 python3）、`sim.py`（没有传感器时造虚拟串口） |
| `source/`、`patches/`、`build/` | 同事源码（含 .git）、我方补丁与说明、离线打镜像的脚本 —— 现场改了源码以后用 |
| `SHA256SUMS` | 校验：`sha256sum -c SHA256SUMS` |

## 1. 接线

**正式部署：X26A 自带的 COM2（/dev/ttyS1）**（用户 2026-10-28 定：传感器 485 直接接 COM2，不用 USB 转 485）
- 先进 BIOS，把 COM2 设成 **RS-485** 模式（缺省是 RS-232）。
- A/B 两根线接到传感器总线的 A/B（接反了读不到，换过来就行）。各传感器的 GND 共地。
- COM2 **没有自动收发切换、没有隔离、没有终端电阻**：
  - 收发方向：同事 1.1.1 没做 RTS 控制，10-09 在 COM2（BIOS 设 485）上实测是通的；读不到时先换 USB 模块排除这一层。
  - 现场有强电干扰，建议外接隔离模块（要不要在问用户）。
  - 终端电阻要在总线末端自己加。
- 启用时不用加 `--serial`，缺省就是 `/dev/ttyS1`。
- 看一下 COM2 在不在：`ls -l /dev/ttyS1`。
- 一条总线上的几台传感器从站地址不能重复。同事的缺省地址：红外 1、局放 2、气体 3、温湿度 4、弧光 5。
- 接口归属（0.17.4，舱室 EG 方案 §4）：EG 的 **LAN1 只接摄像机**，其余（SAM 的传感器、多功能电表）都在 **COM2 这一条 485** 上。电表从站 6（第二块 7），避开传感器的 1–5。烟雾取气体传感器（从站 3）的 `smoke.ppm`，独立颗粒物 PM6 0.18.1 起取消（原来的从站 8 不再用）。
- EG 把打开的传感器（从站地址、挂哪台设备）作为客户端属性 `conv.bus` 报给子站，子站网关页「接口与下挂设备」、EG 本地页「下挂设备 › 485 实际」都按它显示；地址重复时 agent 日志打警告。
- 总线两端各接一个 120 Ω 终端电阻；线短、台数少时不接一般也能通。

**样机 / 调试：USB 转 485 模块**
- 模块插 X26A 的 USB 口，A/B 接总线同上。插上后看一下：`ls -l /dev/serial/by-id/`，能看到一个 `usb-…-port0` 就对了。
- 启用时要加 `--serial /dev/serial/by-id/usb-…-port0`（或 `/dev/ttyUSB0`，会换成 by-id 路径）；不加时只提示，不会自动用 USB。

## 2. 启用

```bash
cd conv-addon-<日期>
sha256sum -c SHA256SUMS                      # 全部 OK
sudo bash install-conv.sh                    # 导入镜像 → 生成配置 → 选串口 → 起转换程序
```

- **串口**：缺省 `/dev/ttyS1`（COM2）；以前记过串口就沿用（改回 COM2 加 `--serial /dev/ttyS1`）。插着 USB 模块只提示一句、不自动用；样机 / 调试要用 USB 就指定：`--serial /dev/ttyUSB0`（会换成 by-id 路径，拔插、重启后不变）。
- **配置**：首次从镜像模板生成 `/opt/lsa-eg/config/conv/`：
  - 设备名按本柜的 `eg.yaml` 生成；
  - 温湿度挂第一台 SAM（`SAM-<柜号>-A`），局放、气体、弧光挂第二台（`SAM-<柜号>-B`）；
  - 局放、气体、温湿度、弧光打开，红外关；
  - 从站地址用同事的缺省值。
- **现场调整**（只改给了的项，改完自动重启转换程序）：
  ```bash
  sudo bash install-conv.sh --sensors pd,arc                    # 只开局放和弧光，其余关
  sudo bash install-conv.sh --addr pd=7,temperature=1           # 改从站地址（1–247）
  sudo bash install-conv.sh --dev temperature=SAM-AH07-B        # 温湿度改挂 B（设备名要在 eg.yaml 里）
  sudo bash install-conv.sh --baud 19200                        # 波特率
  sudo bash install-conv.sh --regen                             # 不要现场改过的了，按模板重新生成（旧的自动备份）
  sudo bash install-conv.sh --rebind                            # 单元换了（拆柜：原来那台改作某个单元）：eg.yaml 里已经没有的设备名改挂到本单元的 SAM，
                                                                 # 从站地址、开关、串口不动，重启后 clientId 换成 lsa-conv-<单元号>（子站推新配置时会自动做）
  ```
  也可以直接改 `config/conv/sensors/*.yaml`，然后 `sudo docker restart lsa-eg-conv`。

## 3. 看结果

1. **状态**：`sudo bash install-conv.sh --status`。显示容器状态、各路传感器的开关、从站地址和挂哪台设备、设备名有没有对上，以及最近 2 分钟的采集日志：「采集成功」就是通了，「采集失败 … TIMEOUT」就是没应答。
2. **本地页**：浏览器开 `http://<EG 地址>/`，用维护账号 maint 登录。
   - 「设备与通信 › 服务状态」：转换程序卡片应显示运行中、最近读数几秒前；下挂设备表里 SAM 有测点数、最近数据。
   - 「实时数据」：选 SAM，看各测点的当前值和质量。
3. **消息格式**：`python3 conv-kit/lsa_check.py --eg-yaml /opt/lsa-eg/config/eg.yaml --duration 120`。跑 2 分钟出报告，看有没有「错误」。
4. 原始日志：`sudo docker logs -f --tail 50 lsa-eg-conv`。

## 4. 读不到时：先绕开转换程序直接问从站

```bash
sudo bash install-conv.sh --diag            # 同事的 rs485_test.py：端口 → 权限 → 打开 → 收发
sudo bash install-conv.sh --diag modbus     # 同事的 pymodbus_diag.py：用 pymodbus 读从站 2 / 1 的寄存器
```

这两条会**先停转换程序**（它占着串口）。诊断脚本在转换程序镜像里跑，X26A 上不用装 Python 包；串口在脚本里看到的是 `/dev/ttyS0`。问完自动重新起转换程序。

排查顺序：
1. 端口在不在：`ls -l /dev/serial/by-id/ /dev/ttyUSB*`。
2. 直接问从站：`--diag`。
3. 还是不通：换 A/B 线，核对从站地址、波特率（传感器面板或说明书），再用 `--addr` / `--baud` 改。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 「串口 … 不存在」 | USB 模块没识别：`dmesg \| tail`；换 USB 口。用 COM2 时检查 BIOS 是否已设成 RS-485 |
| 日志一直「采集失败 … TIMEOUT」 | 没应答。按顺序查：A/B 接反、从站地址、波特率、传感器供电、共地；用 `--diag` 单独问 |
| 部分路成功、部分 TIMEOUT | 失败的那几路地址不对或没接；不接的路用 `--sensors` 关掉 |
| 「!! 转换程序配置的设备名和 eg.yaml 对不上」 | 这几路的数据进不了本地 TB、也不上送。用 `--dev 传感器=设备名` 改成 eg.yaml 里有的名字 |
| 本地页上 SAM 一直「降级」、显示「N 个量异常」 | EG 0.6.1（release-0.17.1）的**已知问题，不是接线问题**：它按「每台 SAM 都接全了各类传感器」判断缺量，按隔室分接时（A 只接温湿度，B 接局放、气体、弧光）另一台缺的量会被标成无效。看实时数据里**接了的那几路**有值、质量正常就行。EG 0.6.2 起按这里打开的传感器判断（`--dev` 挂到哪台就预期哪台有），接全了的就是「在线」 |
| 转换程序卡片「自动重启」次数在涨 | EG 发现转换程序 60 s 没有读数，或者总线重启过，就会重启它。频繁重启时看 `docker logs lsa-eg-conv` |
| 卡片上「重启失败：… error gathering device information … /dev/serial/…」 | USB 模块被拔掉了（或换了口、换了模块），Docker 找不到映射的串口，转换程序起不来。插回去；换了模块就再跑一次 `sudo bash install-conv.sh --serial <新模块的路径>` |
| 重跑了 EG 的 install.sh（升级）以后转换程序没了 | EG 0.6.2 起，启用过的会换成新镜像接着跑。EG 0.6.1（release-0.17.1）的 install.sh 在发布件不带转换程序时会把它关掉：再跑一次 `sudo bash install-conv.sh`，配置还在，不会丢 |
| 现场改了同事的源码 | 改 `source/` 解开的仓库里的 `src/`，然后 `sudo bash install-conv.sh --src <仓库>/src`：把改过的源码挂进容器，不用重打镜像（`--src none` 取消）。正式版本回开发机用 `build/build.sh` 重打 |
| 停用 | `sudo bash install-conv.sh --off`（重跑 EG 的 install.sh 也保持停用） |

## 没有传感器时自测（可选）

```bash
sudo bash install-conv.sh --sim        # 在转换程序容器里跑 sim.py，模拟 5 台传感器（局放 90–130 s 停、温湿度 140–220 s 停、70 s 一次弧光）
sudo bash install-conv.sh              # 测完不带 --sim 再跑一次，回到真串口
```

不要在宿主机上跑 `sim.py` 再用 `--serial` 指过去：虚拟串口（pty）只在创建它的容器里能用，映射进转换程序的容器后打不开（Input/output error）。
