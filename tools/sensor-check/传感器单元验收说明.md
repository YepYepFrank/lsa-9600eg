# LSA-9600 传感器单元验收脚本 使用说明

> 版本 1.1　·　2026-10-29　·　脚本 `sam_check.py`（脚本内版本 1.0）
> 用途：到货检验 / 装柜前，用**一台台架 EG** 逐套验传感器单元 —— 四路 485 传感器 + 双目摄像机（可见光、热像两条视频通路），每套给出「通过」或「哪一路有问题」。

---

## 1. 它测什么

| 部分 | 测的内容 | 判「通过」的条件 |
|---|---|---|
| 局放（超声），从站 2 | 读放电量、次数、类型、等级 | 5 轮都应答；类型 / 等级取值正常；台架上放电量不超过 40 dBμV |
| 气体（烟雾），从站 3 | 读烟雾 ppm、量程 | 5 轮都应答；洁净空气里低于 100 ppm |
| 温湿度，从站 4 | 读湿度、温度 | 5 轮都应答；湿度 0–100 %RH、温度 -40–85 ℃ |
| 弧光 ALS10，从站 5 | 读状态位、故障位、弧光强度、最近一次事件 | 5 轮都应答；没有故障位；READY + MEASURING |
| 功能试验（人配合，可跳过） | 强光照弧光、哈气温湿度、搓手 / 超声发生器对局放、烟靠近气体 | 读数明显上涨（见 §6） |
| 摄像机网络 | LAN1 上摄像机 HTTP 80、RTSP 554 端口 | 都能连上 |
| 摄像机接口（restv1） | 登录、设备信息（序列号 / 固件）、两路流地址、热像全画面温度、两路抓拍 | 登录成功；温度有读数；两张抓拍都是 JPEG（热像 640×480） |
| **视频通路（RTSP）** | 可见光主 / 子码流、热像主 / 子码流，**逐路拉流 4 秒** | 鉴权通过、收到视频包、等到关键帧；报分辨率、帧率、码率 |

脚本**直接问传感器**（Modbus RTU），不经过转换程序；**不改 EG 的任何配置**；只用 EG 系统自带的 `python3`，不装软件、不联网。

## 2. 准备

### 2.1 台架 EG

- 一台 X26A，Ubuntu Server 24.04（装没装 LSA-9600EG 都可以）。
- **用一台还没接入子站的 EG**：脚本会临时停掉转换程序，接入子站的 EG 上会看到通信中断。
- BIOS 里 **COM2 设成 RS-485**。

### 2.2 接线

| 设备 | 接到 EG | 约定 |
|---|---|---|
| 局放、气体、温湿度、弧光 | **COM2**（`/dev/ttyS1`），485 **直接接**，不加隔离中继器、不用 USB 转 485 | 9600 8N1；从站地址 **局放 2、气体 3、温湿度 4、弧光 5** |
| 双目摄像机 | **LAN1** | 摄像机出厂地址 **192.168.1.19**（不改）；EG 的 LAN1 = **192.168.1.1/24** |

485 规定：一条总线只接一只 ALS10，并且放在总线末端（它内置 120 Ω 终端电阻）。

### 2.3 要带的东西

- 维护笔记本（能 SSH 到 EG），或者 U 盘 + EG 接显示器键盘；
- 摄像机两套口令：**RTSP（取流）账号 admin 的口令**、**restv1 接口账号和口令**（真机这两套是分开的）；
- 功能试验道具：手机（闪光灯）、一支香或火柴；有超声发生器更好。

## 3. 部署到 EG

只需要一个文件 `sam_check.py`。放在维护账号的家目录就行。

### 3.1 用网线（scp）

在笔记本上（EG 的 LAN2 地址换成实际的）：

```bash
ssh <维护账号>@<EG 的 LAN2 地址> 'mkdir -p ~/sam-check'
scp sam_check.py <维护账号>@<EG 的 LAN2 地址>:~/sam-check/
```

### 3.2 用 U 盘

在 EG 上：

```bash
lsblk                                   # 找到 U 盘，比如 /dev/sdb1
sudo mount /dev/sdb1 /mnt
mkdir -p ~/sam-check && cp /mnt/sam_check.py ~/sam-check/
sudo umount /mnt
```

### 3.3 部署后检查一遍（1 分钟）

```bash
cd ~/sam-check
sha256sum sam_check.py                  # 与邮件 / 附件里给的 SHA256 对一下
python3 --version                       # 3.8 以上（24.04 自带 3.12）
python3 sam_check.py --help | head -5   # 能打印帮助就说明文件完整
ls -l /dev/ttyS1                        # COM2 在
ip -br addr                             # LAN1 是 192.168.1.1/24
ping -c 2 192.168.1.19                  # 摄像机通（摄像机刚上电要等 1 分钟左右）
```

LAN1 不是 192.168.1.1 时，临时加一个（重启后失效，不改系统配置）：

```bash
sudo ip addr add 192.168.1.1/24 dev <LAN1 网口名>    # 网口名看 ip -br addr
```

## 4. 怎么跑

### 4.1 只测一套

```bash
cd ~/sam-check
sudo python3 sam_check.py --sn <传感器单元编号>
```

- 要 `sudo`：要停 / 起转换程序、开串口。
- 第一次会问摄像机口令（输入时不显示）。装过 EG 的机器会先从 `/opt/lsa-eg/config/local.yaml` 取，取到就不问。
- 功能试验每一项会提示「回车开始 / 输入 s 跳过」。
- 大约 1–3 分钟（含功能试验）。

### 4.2 连续换测（推荐：一台 EG 换一套测一套）

```bash
sudo python3 sam_check.py --loop              # 带功能试验
sudo python3 sam_check.py --loop --no-func    # 只测通路，更快（约 1 分钟一套）
```

每一套的操作：

1. 拔下上一套的 485 接线和摄像机网线，接上新的一套；
2. 在提示「换上下一套，插好后输入编号…」处输入编号（**扫码枪可以直接扫**；直接回车自动编 `unit-001`、`unit-002`…）；
3. 脚本自动：清掉 EG 上摄像机地址的旧 ARP（每台摄像机 IP 相同、MAC 不同）→ **最多等 120 秒**直到四路传感器都应答、弧光过了上电启动抑制、摄像机端口开了 → 全部测一遍；
4. 看屏幕上的大字结论块（见 §5），有问题就按「哪一路」处理或记下来；
5. 继续下一套；全部测完输入 `q` 退出（转换程序这时才起回来）。

### 4.3 摄像机口令免输入（可选）

```bash
sudo LSA_CAM_PASS='<admin 口令>' LSA_CAM_REST_PASS='<接口口令>' \
     python3 sam_check.py --loop --rest-user <接口账号>
```

屏幕和报告里都不会出现口令。

## 5. 看结果

### 5.1 屏幕

每套最后一块：

```
================================================================
  SAM-0002   不通过
  [不通过] 温湿度（从站 4）：5 轮全没读到：没有应答
  [注意] RTSP · 热像主码流：H264 640×480，3.1 帧/秒…（帧率偏低，标称约 9）
================================================================
```

| 级别 | 含义 |
|---|---|
| **通过** | 这一项没问题 |
| **注意** | 能用，但要看一眼（读数偏、帧率低、摄像机像是没换等）；**不算不通过** |
| **不通过** | 这一路有问题，这套不能装柜 |
| 跳过 | 人工跳过的功能试验，或没有这一项 |

一套里只要有一项「不通过」，结论就是「不通过」。

### 5.2 文件

| 模式 | 位置 | 内容 |
|---|---|---|
| 单套 | `~/sam-check/sam-check-<编号>-<时间>/` | `report.txt`（全过程）、`snap-0-visible.jpg`、`snap-1-thermal.jpg`（两路抓拍） |
| 连续换测 | `~/sam-check/sam-check-batch-<时间>/` | `summary.csv`（每套一行：时间、编号、结论、不通过项、注意项、摄像机序列号、MAC、报告路径；Excel 直接打开），每套一个子目录（同上） |

拷回笔记本看抓拍 / 汇总：

```bash
scp -r <维护账号>@<EG 的 LAN2 地址>:~/sam-check/sam-check-batch-* .
```

**抓拍要人看一眼**：可见光画面清楚、热像是热像（不是两路接反），镜头盖摘了。

## 6. 功能试验怎么做

| 项 | 怎么做 | 判通过 | 时限 |
|---|---|---|---|
| 弧光 | 手机闪光灯 / 强光手电**正对探头**照 2–3 秒 | 弧光强度涨 ≥ 1 个百分点（`--arc-rise` 可调） | 30 s |
| 温湿度 | 对着探头进气孔哈气，或用手握住探头 | 湿度涨 ≥ 3 %RH 或温度涨 ≥ 0.5 ℃ | 60 s |
| 局放 | 探头前搓手 / 揉塑料袋，有超声发生器最好（局放 3 秒才刷新一次） | 放电量涨 ≥ 3 dBμV 或放电次数 > 0 | 45 s |
| 气体 | 一支香 / 吹灭的火柴，烟靠近进气口 | 涨 ≥ 20 ppm | 90 s |

- 没看到响应给「注意」而不是「不通过」（刺激手法差异大），人工判断要不要重做。
- **强光可能触发弧光告警**，ALS10 出厂是锁存模式：脚本会提示，按厂家方法复位或给传感器单元断电重启后再装柜。

## 7. 第一次上台架：先验一下脚本本身（10 分钟）

拿一套已知好的传感器单元，按顺序做下面几步，确认脚本判得对，再开始批量：

| 步骤 | 操作 | 应该看到 |
|---|---|---|
| 1 | 全部接好，`sudo python3 sam_check.py --sn 台架自检 --no-func` | 结论「通过」；四路读数合理；四路 RTSP 有分辨率和帧率；两张抓拍画面对 |
| 2 | 拔掉温湿度那一路的 485 线，再跑一次 | 只有「温湿度（从站 4）」不通过，并自动扫地址，列出 2、3、5 |
| 3 | 接回温湿度，拔掉摄像机网线，再跑 | 传感器通过；「摄像机网络」不通过 |
| 4 | 接回网线，`--loop` 跑两套（第二套不换，直接回车） | 第二套给「注意：摄像机已更换 —— 序列号 / MAC 和上一套一样」 |
| 5 | 退出后 `sudo docker ps` | `lsa-eg-conv` 已经起回来（装了 EG 的机器才有） |

任何一步跟表里不一样，把屏幕输出或 `report.txt` 发回来。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 四路全「没有应答」，扫地址也一个都没有 | A+/B- 接反、传感器没供电、BIOS 里 COM2 没设 RS-485、波特率不是 9600 |
| 某一路「没有应答」，扫出一个「不认识」的地址 | 那台地址设错了：`--slave th=14`（举例）先验一下，再让厂家改回约定地址（转换程序也按约定地址读） |
| 「CRC 错」 | 干扰、线太长、两台同地址 |
| 弧光「启动抑制中」 | 刚上电，等半分钟再跑（`--loop` 会自动等） |
| 弧光「故障位」 | 不通过，退厂家 |
| 摄像机 80 / 554 都连不上 | 网线 / PoE 供电；EG 的 LAN1 是不是 192.168.1.1/24；摄像机刚上电要等约 1 分钟 |
| restv1 登录「账号或口令不对」 | 接口账号和 RTSP 账号是两套，别混 |
| restv1 登录「19999 会话满了」 | 摄像机最多 2 个会话：关掉浏览器里的摄像机网页 / 别的调试工具 |
| RTSP「401 鉴权失败」 | RTSP 只认 admin；口令不对 |
| RTSP「SETUP 453 / 454」 | 摄像机会话满（EG 自己的视频服务也在拉），稍后重跑 |
| 热像全画面最高 = 最低 | 镜头盖没摘 / 画面没内容 |
| 热像通道出现高清分辨率 | 两路接反或摄像机配置不对 |
| 提示「串口还被别的进程开着」 | 有别的程序占着 COM2，按提示停掉 |
| 脚本被强行杀掉后转换程序没起 | `sudo docker start lsa-eg-conv` |

## 9. 参数速查

| 参数 | 用途 |
|---|---|
| `--sn <编号>` | 单套模式的编号（写进报告和目录名） |
| `--loop` | 连续换测 |
| `--no-func` | 不做功能试验 |
| `--no-cam` / `--cam-only` | 不测摄像机 / 只测摄像机 |
| `--only th,arc` | 只测这几路（键：`pd` 局放、`gas` 气体、`th` 温湿度、`arc` 弧光） |
| `--slave th=14` | 某一路地址不是约定值 |
| `--scan` / `--scan 1-247` | 主动扫地址 |
| `--rounds 20` | 每路多问几轮（看通信稳不稳） |
| `--wait 180` | 换测时最多等设备上线几秒（缺省 120） |
| `--rtsp-secs 10` | 每路拉流秒数（缺省 4） |
| `--cam <地址>` | 摄像机地址（缺省先取 local.yaml，再没有用 192.168.1.19） |
| `--rest-user <账号>` | restv1 接口账号 |
| `--port /dev/ttyUSB0` | 换串口（正式部署不用） |

退出码：全部通过 0，有不通过 1，参数 / 环境问题 2。
