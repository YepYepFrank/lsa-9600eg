# 转换程序 MQTT 补丁说明（edge-gateway，2026-10-13）

> **给谁看**：写 edge-gateway（传感器转换程序）的同事。
> **为什么是我们改**：用户 10-13 定了分工 —— 和本机总线（Mosquitto）打交道的部分（连接、发布、补传）以及接进 EG 的部署归 EG 方；你只改传感器解析（《转换程序联调意见》第一、二部分）。
> **改了哪些文件**：只有两个 —— `src/north/mqtt_client.py`、`src/core/app.py`。其余文件一个字没动，你的驱动、调度、缓存库、补传批量逻辑都照旧。

## 1. 改了什么（对应联调意见第 1、2、10 条）

| # | 问题（联调实测） | 现在 |
|---|---|---|
| 1 | Mosquitto 断开后再也不重连，之后数据只进缓存、也不补传；开机时总线比程序晚起，第一次连不上就再也不连 | `InternalMQTTClient.run()` 常驻：断开后每 `reconnect_interval`（3 s）重连，**启动时连不上也一直重试**；每次连上**先发 attributes，再马上触发补传** |
| 2 | 发布卡住时一次阻塞 10 s，这段时间弧光、局放都没采（「轮询耗时超过快变量周期」） | **采集和发布分开**：采到的数据只放进队列（`_pub_queue`），由单独的发布任务发；发布加 2 s 超时（`publish_timeout`），超时 / 出错就当断线、这条转入缓存，不会再挂住轮询 |
| 10 | clientId 固定 `lsa-conv-eg` | `lsa-conv-<柜号>`：柜号从 EG 只读挂进来的 `eg.yaml`（环境变量 `LSA_EG_YAML`，缺省 `/eg/eg.yaml`）的 `cabinet.code` 取；取不到用配置里的 `client_id`；配置还是老的 `lsa-conv-eg` 时从设备名推（`SAM-AH03-B` → `lsa-conv-AH03`） |
| — | （顺手）缓存库要等第一次写缓存才打开：程序重启后，上次没补传完的缓存要等下一次断线才会补 | 启动时就打开缓存库，连上就补 |
| — | （顺手）关闭时队列里还没发的会丢 | 关闭时转入缓存，下次启动补传 |

另外：总线地址可以用环境变量 `LSA_MQTT_URL`（如 `mqtt://127.0.0.1:1884`）覆盖，EG 的 compose 会给。`gateway.yaml` 的 `mqtt:` 段可以加两项（不加用缺省）：`publish_timeout: 2`、`connect_timeout: 5`。

**接口没变**：`publish_telemetry(ts, values)`、`publish_telemetry_batch(list)`、`publish_attributes(dict)`、`is_connected` 都还在，没连上 / 超时返回 `False`；`HealthMonitor`、`DataReplayer._replay_batch` 不用改。`DataReplayer.start_replay()` 不再用（补传改由 `app.py` 的 `_replay_loop` 在每次连上时触发、发到缓存空为止，平时每 `replay_interval` 秒也查一次）。

## 2. 怎么合入

**推荐**：用本目录的两个文件直接覆盖你的同名文件（`src/north/mqtt_client.py`、`src/core/app.py`）。你这两个文件在我们拿到之后要是又改过，就看 `edge-gateway.patch` 手工合：

```bash
cd edge-gateway
patch -p1 --dry-run < edge-gateway.patch      # 先试；全部 succeeded 再去掉 --dry-run
patch -p1 < edge-gateway.patch
```

> 注：你的原文件是 CRLF 换行，补丁是按 LF 生成的（diff 时忽略了换行差异）。直接覆盖最省事；要 patch 的话先 `dos2unix src/north/mqtt_client.py src/core/app.py`。

依赖没变（aiomqtt 2.x、aiosqlite、pyserial、PyYAML）。

## 3. 我们怎么验的

模拟器（`sim.py`，在虚拟串口上模拟 5 台传感器）+ 你的程序（只改上面两个文件、配置里串口指到虚拟串口并打开弧光）+ 一次性 Mosquitto 2.1.2 容器（与 EG 同版本同配置），依赖全部用你 `wheels/` 里的包 + pyserial 3.5 离线装。一个持久会话的记录器订阅 `lsa/#` 收下所有消息。三种情况连着做：

| 情况 | 做法 | 结果 |
|---|---|---|
| a. 总线卡住 | `docker pause` 60 s 后 `unpause` | 总线恢复后 0.2 s 内重连（暂停期间每 3 s 试一次、每次 5 s 超时，没挂住采集）；补传 71 条，弧光 31 个、气体 5 个采样全部补上，`ts` 是原采样时刻 |
| b. 总线重启 | `docker restart` Mosquitto 容器 | 2 s 后重连；补传 3 条（重启那几秒的），没有空洞 |
| c. 程序先于总线启动 | 先停 Mosquitto，再重启你的程序，30 s 后才起 Mosquitto | 程序在没有总线时启动，循环重试，总线起来 6 s 后连上；补传 44 条（含程序重启前缓存的），弧光 16 个、气体 3 个采样全部补上。唯一的 3.8 s 空洞是程序自己被重启的那几秒（进程不在跑） |

复测（我们这边，需要 Docker 与本机已有的 `python:3.12-slim`、`eclipse-mosquitto:2.1.2` 镜像，不联网）：

```bash
bash test/prep.sh <edge-gateway 源码目录> <pyserial-3.5-py2.py3-none-any.whl> <工作目录>   # 复制源码、覆盖补丁、断网装依赖
bash test/run.sh <工作目录>                                                              # 约 6 分钟，三种情况连着做
python3 test/analyze.py <工作目录>                                                       # 每种情况的重连、补传、ts、轮询
```

判据：恢复后自动重连；断开期间的数据经缓存补传、**一条不少**（弧光 2 s、气体 10 s 两路的采样时刻序列没有空洞）；补传的 `ts` 是原采样时刻；断开期间轮询周期不受影响（采样时刻间隔照旧 2 s，日志没有「轮询耗时超过快变量周期」）。

三种情况下「轮询耗时超过快变量周期」都是 0 次（补丁前总线卡住时一次发布阻塞 10.4 s）；没有收到重复数据。

## 4. 还要你改的（不在这个补丁里）

见《转换程序联调意见》第一、二部分：弧光事件按类型处理（只有类型 1 发 `uv.pulse`）、设备名按传感器配 / `dev.*` 汇总、不发 `ir.*` / `alarm_status` / 本机 CPU 内存、局放 3 s 与地电波 / 特高频、`smoke.ppm` 等。改设备名按传感器配的时候请告诉我们：缓存表现在只记了传感器名，补传时一律发到一个设备名下，到时候我们一起把补传按设备名分开。
