# 转换程序 MQTT 补丁说明（edge-gateway，**基于 1.1.0**，2026-10-13）

> **给谁看**：写 edge-gateway（传感器转换程序）的同事。
> **基于哪一版**：**1.1.0**（`edge-gateway02.rar`，README 版本 1.1.0）。第 1 轮那份补丁是按 1.0 做的，作废。你以后发新版本时请在 README 写清版本号；最好直接用 git 交代码，我们按提交合补丁，不会再做到旧版本上。
> **为什么是我们改**：用户 10-13 定了分工 —— 和本机总线（Mosquitto）打交道的部分（连接、发布、缓存补传）以及接进 EG 的部署归 EG 方；你只改传感器解析（第 2 轮联调意见第二部分：弧光事件轮询等）。
> **改了哪些文件**：4 个 —— `src/core/app.py`、`src/north/mqtt_client.py`、`src/storage/db.py`、`src/storage/cache.py`。驱动、调度器、标准化、分析引擎、健康监控、看门狗、`replay.py` 一个字没动。

## 1. 改了什么（对应第 2 轮联调意见第三部分 A–E）

| # | 1.1.0 的问题（联调实测） | 现在 |
|---|---|---|
| A | `_on_sensor_data` 每条读数都 `cache.save`，补传任务每 5 s 又把缓存发一遍 → **所有数据发两遍**（123 个重复时刻、大量「ts 往回走」，弧光脉冲也发两次） | 采集回调只把读数放进发布队列；**只有发布失败（没连上 / 超时）的才进缓存** |
| B | 总线卡住时一次发布阻塞 13.1 s，这段时间不采集 | 采集和发布分开：单独的发布任务发，发布 2 s 超时（`publish_timeout`），超时就当断线、这条转入缓存 |
| C | `mqtt_client` 只有一个设备名，所有读数都发到 `lsa/SAM-AH03-B/…`（温湿度配成 A 隔室也发到了 B，A 隔室在 EG 看来一直没数据，`dev.*` 又混到一起） | **按读数所属传感器 yaml 的 `device:` 发到 `lsa/<device>/telemetry`**；缓存表加 `device` 列（老库启动时自动加列，老记录按传感器名推回设备名），补传按设备分组；每次连上给每个设备名各发一次 attributes |
| D | clientId 仍是 `lsa-conv-eg` | `lsa-conv-<柜号>`：柜号从 EG 只读挂进来的 `eg.yaml`（环境变量 `LSA_EG_YAML`，缺省 `/eg/eg.yaml`）的 `cabinet.code` 取；取不到用配置的 `client_id`；还是老的 `lsa-conv-eg` 时从设备名推 |
| E | 去掉了 SIGTERM 处理，容器停止时来不及收尾 | SIGTERM / SIGINT 优雅退出：停采集，**队列里没发的转入缓存**，再关库（下次启动补传） |

**重连只留一套**：用 `InternalMQTTClient.run()` 常驻 —— 断线每 3 s 重连、启动时连不上也一直重试、每次连上先发 attributes 再触发补传。你在 1.1.0 加的 `_mqtt_reconnect_loop` 和 `DataReplayer.start_replay()` 不再启动（两套并存会抢着连、抢着补）。

**ts 不往回走**：重连后先把缓存（同一设备按 ts 升序）补完，补完才放行实时数据。同一设备收到的 ts 是单调的。

**其余**：总线地址可以用环境变量 `LSA_MQTT_URL`（如 `mqtt://127.0.0.1:1884`）覆盖，EG 的 compose 会给。`gateway.yaml` 的 `mqtt:` 段可以加 `publish_timeout: 2`、`connect_timeout: 5`（不加用缺省）。总线卡住时 aiomqtt 留下的「Future exception was never retrieved」只记 debug，不再刷屏。

## 2. 怎么合入

**推荐**：用本目录 `src/` 下的 4 个文件直接覆盖你 1.1.0 的同名文件。你这几个文件在 1.1.0 之后要是又改过，就看 `edge-gateway.patch`（相对 1.1.0 的 diff）手工合：

```bash
cd edge-gateway
patch -p1 --dry-run < edge-gateway.patch      # 先试；全部 succeeded 再去掉 --dry-run
patch -p1 < edge-gateway.patch
```

> 注：你的原文件是 CRLF 换行，补丁按 LF 生成（diff 时忽略了换行差异）。直接覆盖最省事；要 patch 的话先 `dos2unix src/core/app.py src/north/mqtt_client.py src/storage/db.py src/storage/cache.py`。

依赖没变（aiomqtt 2.x、aiosqlite、pyserial、PyYAML）。缓存库不用删：新程序第一次启动会自动给老表加 `device` 列。

## 3. 我们怎么验的

模拟器（conv-kit 的 `sim.py`，虚拟串口上 5 台传感器）+ 你的 1.1.0（只换上面 4 个文件；配置里串口指到虚拟串口、打开弧光、**温湿度的 `device` 改成 `SAM-AH03-A`**）+ 一次性 Mosquitto 2.1.2（与 EG 同版本同配置），依赖全部用你 `wheels/` 里的包在断网容器里装。一个持久会话的记录器订阅 `lsa/#` 收下全部消息，conv-kit 检查工具 `lsa_check.py` 1.1 全程看着。三种情况连着做：

| 情况 | 做法 | 结果 |
|---|---|---|
| a. 总线卡住 | `docker pause` 60 s 后 `unpause` | 恢复后 1 s 内重连（暂停期间每 3 s 试一次、每次 5 s 超时，不挂住采集）；补传 44 条（按设备分组），弧光 15 个、气体 6 个采样全部补上，`ts` 是原采样时刻 |
| b. 总线重启 | `docker restart` Mosquitto 容器 | 3 s 后重连；补传 2 条，没有空洞 |
| c. 程序先于总线启动 | 先停 Mosquitto，再重启你的程序，30 s 后才起 Mosquitto | 程序收到 SIGTERM 优雅退出（「停止时队列里 2 条没发，已转入缓存」）；新程序在没有总线时启动、循环重试，总线起来 6 s 后连上，补传 27 条（含上一个进程留下的），弧光 8 个、气体 4 个采样全部补上。唯一的 6.4 s 空洞是程序自己被重启的那几秒 |

另外几项：

| 项 | 结果 |
|---|---|
| 重复发送（A） | 0 条（1.1.0 原来每条都发两遍） |
| 按设备发（C） | `SAM-AH03-A` 收到温湿度 36 条、`SAM-AH03-B` 收到其余 242 条；每次连上两个设备名各发一次 attributes（各 4 次） |
| lsa_check 1.1 全程 | 「dev.fails 回 0 又跳回（dev.* 互相覆盖）」**0**、「ts 往回走」**0** |
| 记录器逐条核对 | 同一设备同一个量的 ts 往回走 0 次 |
| 轮询 | 「轮询耗时超过最小组周期」5 次，全在模拟器局放不应答那 40 s 里（每次 = 两次 0.5 s 串口超时），和发布无关；b、c 期间 0 次 |

> 注：1.1.0 的弧光实测每约 3.8 s 才出一个采样（驱动每轮在 1.8 s 窗口里反复查事件，见第 2 轮意见第二部分第 1 条），所以弧光空洞按实测间隔判，不按标称 2 s。

复测（我们这边，需要 Docker 与本机已有的 `python:3.12-slim`、`eclipse-mosquitto:2.1.2` 镜像，不联网）：

```bash
bash test/prep.sh <edge-gateway 1.1.0 源码目录> <pyserial-3.5-py2.py3-none-any.whl> <工作目录>
bash test/run.sh <工作目录>                  # 约 7 分钟，三种情况连着做，lsa_check 全程看着
python3 test/analyze.py <工作目录>           # 重连、补传、ts、按设备、lsa_check 结论
```

## 4. 还要你改的（不在这个补丁里）

见第 2 轮联调意见第二部分：**弧光事件轮询**做成单独的高频小任务（每 100–200 ms 读一次 0x0100）、读到新事件立即交出去且 `ts` 用读到的那一刻、每个事件单独一条；Modbus 串口打不开时循环重试；同一时刻同一设备合成一条消息。
