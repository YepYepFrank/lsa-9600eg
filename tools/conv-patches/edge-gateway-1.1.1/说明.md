## 七个补丁（一个提交一处）

| 文件 | 改什么 | 为什么 |
|---|---|---|
| `0001-A-clientId-lsa-conv-cabinet.patch` | MQTT clientId 用 `lsa-conv-<柜号>`。柜号取 EG 只读挂进容器的 `/eg/eg.yaml` 的 `cabinet.code`，环境变量 `LSA_EG_YAML` 可改路径。取不到时用 `gateway.yaml` 里的 `client_id` | 一台总线上 clientId 重复会互相踢下线 |
| `0002-B-attributes-each-device.patch` | 连上后，给每个传感器 yaml 里配的 `device` 各发一次 attributes（以前只发给 `device.name`）。重连循环里重复的那次去掉，因为 `connect()` 里已经发过 | 以前 `SAM-AH03-A` 一次都收不到 |
| `0003-C-sigterm-flush-to-cache.patch` | 收到 SIGTERM / SIGINT 时走正常停止。设备缓冲里还没发的先尝试发出，发不了就转入缓存，下次启动补传。原来的 `_flush_remaining_buffers` 写好了但没被调用，而且没连上时不进缓存，这里一并修了 | `docker stop` 发的是 SIGTERM，以前缓冲里的数据会丢 |
| `0004-D-cache-device-replay-by-device.patch` | 缓存表加 `device` 列，缓存时记下设备名。老库启动时自动补上这一列（`ALTER TABLE`），老记录按配置里的「传感器 → 设备」回填。补传按设备分组，各发到 `lsa/<设备名>/telemetry`，发成功的才删；配置里查不到的老记录仍发到 `device.name` | 以前缓存不记设备名，补传一律发到 `device.name`：A 隔室的温湿度补传时跑到了 B 下面。补传归我方，所以由我们改 |
| `0005-E-env-overrides-heartbeat.patch` | ① 读完 `gateway.yaml` 后，环境变量 `LSA_MQTT_URL`（如 `mqtt://127.0.0.1:1884`，可带 `user:pass@`）覆盖 `mqtt.host/port/username/password`，`LSA_SERIAL` 覆盖 `serial.port`；没设就照旧用 yaml 里的。② 有数据发出或写进缓存时，更新心跳文件 `/data/heartbeat`（`LSA_HEARTBEAT` 可改路径，5 s 最多写一次） | ① 总线地址和串口由 EG 的编排统一给，现场换串口不用进容器改配置。② EG 的健康检查要能看出「程序还在干活」，光看进程在不够 |
| `0006-F-clientId-unit-code.patch` | （2026-10-18，舱室 EG 0.7.0）clientId 先取 eg.yaml 顶层 `unit.code`（如 `lsa-conv-AH01-A`），没有再取 `cabinet.code`。只改 0001 加的那个函数 | 0.18.0 起一个电气舱室一台 EG，同一面柜的两台各跑一个转换程序；照旧一柜一台的 eg.yaml 没有 unit 段，clientId 与以前一样 |
| `0007-G-meter-generic-modbus.patch` | （2026-10-19，S19）新加「电表」一路：`src/drivers/meter.py`（通用 Modbus 寄存器表驱动）、`app.py` 驱动表加 `meter`、`config/sensors/meter.yaml`（缺省关）。读哪几段寄存器、每个量的地址 / 数据类型（uint16 / int16 / uint32 / int32 / float32）/ 字序 / 倍率、表内变比，全在 meter.yaml 里，**型号定了只换表、不改程序**。一段读失败这一轮整台算失败（dev.fails 往上数），不发半截数；谐波这类分钟档的段用 `every` 隔着读；`count` + `json` 发成 JSON 字符串数组（点目录 `el.hu.*` / `el.hi.*`）。按 EG内部MQTT格式 §5.2 发二次值；表计内部设了变比、读出来已是一次值的，在 meter.yaml 填 `ratio.pt / ratio.ct`，按每个量的 `ratio: pt / ct / ptct` 除回二次值。**现在的寄存器表是占位的**（S19 电表型号 / 点表还没定），来了照表计手册改那一个文件 | S19 每面开关柜一只电表 PM-<柜号>，挂在该柜第一个单元的 EG 上，跟 SAM 的 5 路在同一条 485（COM2，从站 6）。COM2 只能一个进程占，所以必须由你的程序读、走同一个 ModbusRTUClient 和轮询循环，不能另起程序抢串口。EG 的 install-conv.sh 按 eg.yaml 自动开关这一路、填设备名和从站号 |

## 怎么合

在你的仓库里（当前就是 316e619，或者在它之后、没动过这两个文件的提交上）：

```bash
cd edge-gateway
git am --3way /路径/000*.patch        # 0001–0007 按文件名顺序打
git log --oneline -8      # 应多出 7 个提交
```

- 先试一下：`git apply --check /路径/*.patch`，没有输出就是能打上。
- 有冲突时，`git am` 会停下来。改好后 `git add` 相关文件，再 `git am --continue`；不想要了就 `git am --abort`。
- 补丁是 LF 换行，你那边 `core.autocrlf=true` 也没关系。

**顺便提醒**：316e619 里 `config/gateway.yaml` 的 `serial.port` 提交成了 `"/tmp/arc_master"`，那是你自己测试用的虚拟串口。发给 EG 部署前请改回 `"/dev/ttyS1"`（X26A 的 485 口），或者由部署时的 `--conv-serial` 决定。
