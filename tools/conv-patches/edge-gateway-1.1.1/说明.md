## 三个补丁（一个提交一处）

| 文件 | 改什么 | 为什么 |
|---|---|---|
| `0001-A-clientId-lsa-conv-cabinet.patch` | MQTT clientId 用 `lsa-conv-<柜号>`。柜号取 EG 只读挂进容器的 `/eg/eg.yaml` 的 `cabinet.code`，环境变量 `LSA_EG_YAML` 可改路径。取不到时用 `gateway.yaml` 里的 `client_id` | 一台总线上 clientId 重复会互相踢下线 |
| `0002-B-attributes-each-device.patch` | 连上后，给每个传感器 yaml 里配的 `device` 各发一次 attributes（以前只发给 `device.name`）。重连循环里重复的那次去掉，因为 `connect()` 里已经发过 | 以前 `SAM-AH03-A` 一次都收不到 |
| `0003-C-sigterm-flush-to-cache.patch` | 收到 SIGTERM / SIGINT 时走正常停止。设备缓冲里还没发的先尝试发出，发不了就转入缓存，下次启动补传。原来的 `_flush_remaining_buffers` 写好了但没被调用，而且没连上时不进缓存，这里一并修了 | `docker stop` 发的是 SIGTERM，以前缓冲里的数据会丢 |

## 怎么合

在你的仓库里（当前就是 316e619，或者在它之后、没动过这两个文件的提交上）：

```bash
cd edge-gateway
git am --3way /路径/0001-A-clientId-lsa-conv-cabinet.patch /路径/0002-B-attributes-each-device.patch /路径/0003-C-sigterm-flush-to-cache.patch
git log --oneline -4      # 应多出 3 个提交
```

- 先试一下：`git apply --check /路径/*.patch`，没有输出就是能打上。
- 有冲突时，`git am` 会停下来。改好后 `git add` 相关文件，再 `git am --continue`；不想要了就 `git am --abort`。
- 补丁是 LF 换行，你那边 `core.autocrlf=true` 也没关系。

**顺便提醒**：316e619 里 `config/gateway.yaml` 的 `serial.port` 提交成了 `"/tmp/arc_master"`，那是你自己测试用的虚拟串口。发给 EG 部署前请改回 `"/dev/ttyS1"`（X26A 的 485 口），或者由部署时的 `--conv-serial` 决定。

## 我们怎么验的

模拟器（conv-kit 的 `sim.py`，虚拟串口上模拟各传感器）+ 你的仓库（`git am` 打上这 3 个补丁，另跑一遍不打的作对照）+ 一次性 Mosquitto 2.1.2，依赖全部用你 `wheels/` 里的包断网安装。测试时把温湿度、局放、气体也打开，并把温湿度挂到 `SAM-AH03-A`（你提交的配置只开了弧光）。三种情况连着做：总线暂停 60 s、总线重启、程序先于总线启动。

| 项 | 不打补丁 | 打上补丁 |
|---|---|---|
| clientId（总线日志） | `lsa-conv-eg` | `lsa-conv-AH03` |
| attributes 次数 | `SAM-AH03-A` 0 次，`SAM-AH03-B` 7 次（每次连上发两遍） | 两个设备各 4 次（每次连上各一次） |
| 程序被 `docker restart`（SIGTERM） | 直接被杀，没有停止日志 | 「边缘网关停止中… / 已停止」，1 秒内正常退出 |
| 停止时缓冲里还有没发的（直接检验 `test/test_c.py`） | 转入缓存 0 条（丢了） | 转入缓存 2 条，日志「停止时队列里 2 条没发出，已转入缓存」 |
| 三种情况下的重连、补传 | 都能重连，补传完整 | 同左，没有变差 |
| lsa_check 1.1 全程 | 错误 261、注意 150 | 错误 227、注意 109；**没有新增的错误类型** |

## 不在这三个补丁里、请你看一下的（两边都有，不是补丁带来的）

- **同一设备名下几路传感器的 `dev.*` 互相覆盖**：lsa_check 报「dev.fails 回 0 又跳回」两百多次。测试里 `SAM-AH03-B` 下有弧光、局放、气体三路，每路都各发自己的 `dev.*`。按《EG内部MQTT格式》§6b，要汇总后再发：fails 取各路最大、last_ok 取最早。你提交的配置只开了弧光，所以平时看不到。
- **补传时设备名不对**：缓存表里没有设备名，补传一律发到 `device.name`（`SAM-AH03-B`），所以 `SAM-AH03-A` 的温湿度补传时跑到了 B 下面。请在缓存里记下设备名，补传时按设备名分开发。
- **`ts 往回走`**：补传和实时数据交错发出造成的，就是第 3 轮意见的 D 项。TB 按 ts 覆盖，不影响数据。
